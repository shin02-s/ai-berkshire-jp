# 日本株調査記事：著者・編集者・読者の3 Agent共同制作

## 設計思想

調査レポートを短くするだけではなく、読者が事業の仕組み、重要な数字、反対意見、評価、行動条件を一読で理解できる日本語記事へ変換する。WeChat向けの公開工程は維持するが、対象銘柄と投資分析は日本株に限定する。

## フェーズ1：調査と素材整理

### ステップ1：記事の位置付けを決める

- 対象会社、証券コード、記事の中心となる一つの問い。
- 想定読者、既知事項、読後に理解してほしい判断。
- 解説、決算レビュー、仮説更新、業界比較のどれか。
- 調査日とデータ基準日。

### ステップ2：深度調査を確認する

元になる調査がない場合は先に適切な `-jp` 調査スキルを使う。財務数値は `skills/financial-data-jp.md` に従い、会社IR、EDINET、TDnet、JPXを優先する。海外企業は競争・顧客・供給網の背景に限る。

### ステップ3：素材を整理する

| 素材 | 内容 |
|---|---|
| 中核事実 | 一次資料で確認済みの数字・出来事 |
| 推論 | 事実から導く解釈と前提 |
| 反対意見 | 賢い非保有者が買わない理由 |
| 評価 | 円建て倍率、三情景、織り込み期待 |
| 行動条件 | 何を観測し、どの条件で判断を変えるか |

素材にない数字や結論を記事化の都合で追加しない。

素材を確定したら、TeamCreateを利用できる場合は `{会社名}-article-jp` を作り、TaskCreateで著者タスクを登録する。利用できない場合は同じ役割を順番に実行し、各工程の成果を混ぜる前に保存する。

## フェーズ2：著者Agentが初稿を書く

### 著者Agentのプロンプト

```text
あなたは日本株の長文記事を執筆する著者です。

対象：{会社名}（{証券コード}）
中心の問い：{問い}
想定読者：{読者}
調査素材：
{検証済み素材}

要件：
- 冒頭で読者の具体的な疑問を提示する。
- 誰が何に払い、利益を動かす変数が何かを説明する。
- 抽象的な称賛より、数量、単価、費用、資産、意思決定を描く。
- 競争優位と最大の反対意見を同じ強さで扱う。
- 政策保有株、親子上場、支配株主、少数株主保護等が重要なら含める。
- 円建て評価と、現在価格が織り込む期待を示す。
- 最後に観測指標と判断変更条件を置く。
- 根拠のない将来予言、煽り、本人になりきった発言を避ける。

出力：見出し、本文、表、図版挿入位置、出典注記を含む完全なMarkdown初稿。
```

### 記事の既定構成

1. 読者が抱く問い。
2. 会社と今回の結論を理解するための基本データ。
3. 会社が何で稼ぐか。
4. 利益を動かす2〜3個の変数。
5. 競争優位と、それを壊すもの。
6. 経営・資本配分・ガバナンス。
7. 最強の弱気論。
8. 円建て評価と三情景。
9. 未保有者・保有者別の判断条件。
10. 出典、制約、免責事項。

### 図版・数式

- 図は産業チェーン、売上構成、利益要因、シナリオ比較など、理解を明確に改善する場合だけ使う。
- 図の挿入位置に説明、必要データ、軸、単位、出典を書く。
- 数式は変数を定義し、円・株・百万円等の単位を揃える。
- 装飾目的の画像や未検証のチャートを作らない。

著者Agentは完了後、TaskUpdateとSendMessageで初稿を返す。

## フェーズ3：編集Agentと読者Agentが並行レビューする

初稿受領後、TaskCreateで編集と読者レビューの2件を登録し、同じメッセージ内で両Agentを並行起動する。互いのレビューを先に見せず、完了時にTaskUpdateとSendMessageで結果を返す。

### 編集Agent

次を確認し、問題箇所、理由、修正案を表で返す。

- 結論と証拠の対応。
- 数字、期間、単位、会計基準、用語の一貫性。
- 重複、脱線、論理の飛躍、主語不明、過剰な形容。
- 見出し順、表の読みやすさ、図版の必要性。
- 強気論と弱気論の公平性。
- 投資助言と誤認される断定表現。

### 読者Agent

一般の長期投資家として次へ回答する。

1. 一読で会社の稼ぎ方を説明できるか。
2. 最も重要な数字は何か。
3. 買わない理由が十分に分かるか。
4. 現在価格が高いか安いかの根拠が分かるか。
5. 何を待てば判断できるか。
6. 分からない用語・表・段落はどこか。
7. 記事が答えていない最重要質問は何か。

総合評価、良い点、必須修正、任意改善、一文総評を返す。

## フェーズ4：定稿する

### ステップ1：フィードバックを統合する

事実誤りと理解障害を最優先し、好みだけの修正は採否を明示する。編集者と読者の意見が衝突した場合は、正確性、読者理解、元資料への忠実性の順で判断する。

### ステップ2：修正する

修正で新しい主張が生じた場合は出典を確認する。数値や結論を変えた場合は関連する表、要約、図版、行動条件も連動更新する。

### ステップ3：図版を準備する

既存の検証済み図版がある場合は再利用する。元資料から切り出す場合は出典とページを記録し、可読性を確認する。著作権や利用条件が不明な画像を転載しない。

### ステップ4：最終ファイルを作る

- 調査版：`reports/{会社名}/{会社名}-article-source-{YYYYMMDD}.md`
- 公開稿：`reports/{会社名}/{会社名}-article-{YYYYMMDD}.md`
- 図版：`assets/{会社名またはテーマ}/fig{番号}-{説明}.png`

既存ファイルは上書きしない。末尾に一次資料、主要な補助資料、データ基準日、調査上の制約を置く。

```bash
python tools/report_audit.py --locale ja extract --market jp --report {公開稿}
python tools/report_audit.py --locale ja verdict --market jp --results '<照合済みJSON>' --report {公開稿名}
```

監査不合格なら公開稿ではなくドラフトとする。

公開稿またはドラフトの保存後、全成果物と未処理メッセージを確認する。各Agentへ `shutdown_request` を送り、終了応答後にTeamDeleteでチームを整理する。失敗したタスクがある場合は、欠損を表示するか再試行するまで削除しない。

## 執筆上の禁止事項

- 元資料にない数字、発言、出来事を創作しない。
- 海外上場銘柄を投資候補や評価比較へ広げない。
- 一時的な株価反応を事業価値の変化と断定しない。
- 企業を根拠なく「日本版の別企業」と呼ばない。
- 読者の注意を引くためにリスクや確信度を誇張しない。
- 本プロジェクトが学習・調査目的であることを明記する。
