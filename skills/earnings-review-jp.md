# 日本企業の決算精読：一次資料による深度レビュー

## 設計思想

決算の良し悪しを見出しや進捗率で決めず、損益、CF、財政状態、注記、経営説明、過去の約束を一体で読む。対象は東証内国普通株とする。

## 実行フロー

### 事前段階：資料可得性を評価する

| 評価 | 状況 | 扱い |
|---|---|---|
| A | 短信、説明資料、質疑、法定開示が揃う | 全工程を実行する |
| B | 一部資料や比較期間が欠ける | 欠損と代替資料を明示する |
| C | 一次資料を取得できない | 第三者集計を正本とせず、精読不能または低信頼とする |

### ステップ1：一次資料を取得する

1. 会社IRまたはTDnetの決算短信。
2. 決算説明資料、補足データ、質疑応答。
3. EDINETの有価証券報告書・半期報告書。
4. 前年同期資料、前回会社計画、中期計画。
5. 配当、自己株式取得、増資、M&A等の同時開示。

発表日、対象期間、連結・単体、会計基準、決算期変更、組替えを確認する。

### ステップ2：財務数値を抽出・検証する

#### 2.1 損益

| 項目 | 当期 | 前年同期 | 増減 | 会社計画 | 要因 |
|---|---:|---:|---:|---:|---|

売上高、売上総利益、営業利益、税引前利益、親会社株主帰属利益、EPSを確認する。数量、単価、製品構成、為替、原材料、人件費、稼働率、一時損益へ分解する。

#### 2.2 キャッシュフロー

営業CF、設備投資、FCF、買収・売却、配当、自己株式取得、借入を比較する。利益と営業CFの乖離、運転資本、税支払を説明する。

#### 2.3 財政状態

現預金、有利子負債、リース、在庫、売掛金、のれん、減損、引当金、年金、政策保有株を確認する。

#### 2.4 株式数と評価

自己株式、分割、潜在株式、期中平均株式数、期末株式数を分ける。

```bash
python tools/financial_rigor.py --locale ja cross-validate --field {項目} --values '{"決算短信":0,"有価証券報告書":0}' --unit 百万円
python tools/financial_rigor.py --locale ja verify-market-cap --price {株価} --shares {株式数} --reported {時価総額} --currency JPY
python tools/financial_rigor.py --locale ja verify-valuation --price {株価} --eps {EPS} --bvps {BPS} --dividend {配当}
```

数値が不一致なら平均せず、期間、単位、連結範囲、会計基準、訂正、株式分割を調べる。

### ステップ3：経営者説明を精読する

#### 3.1 語調

需要、価格、コスト、投資、リスクについて、断定、慎重化、削除、順序変更を前回資料と比較する。

#### 3.2 約束の追跡

| 過去の約束 | 期限 | 今回の結果 | 判定 | 説明 |
|---|---|---|---|---|

達成、進行、延期、撤回、目標変更へ分類する。

#### 3.3 会社計画

据置・修正の理由、下期必要額、季節性、受注、能力増強、為替前提を確認する。進捗率だけで達成可能性を判断しない。

### ステップ4：注記と隠れた変化

- 収益認識、棚卸資産評価、引当金、減損、税効果。
- セグメント変更、連結範囲、非継続事業、取得・売却。
- 関連当事者取引、支配株主、非支配持分。
- 偶発債務、訴訟、保証、財務制限条項。
- 政策保有株の売却、持合い解消、親子上場の方針。
- 後発事象と監査上の主要検討事項。

異常信号として、利益増加とCF悪化、在庫・売掛金の急増、頻繁な指標変更、一時益依存、説明の後退を確認する。

### ステップ5：履歴と比較する

3〜5年の売上、利益率、ROE、ROIC、営業CF、設備投資、株式数、配当を並べる。循環、構造、一時要因を分ける。

### ステップ6：決算精読レポートを作る

1. 一文判定。
2. 基本情報と資料一覧。
3. 主要KPI表。
4. 利益変動の要因分解。
5. CFと財政状態。
6. 注記・会計上の注意点。
7. 経営者の語調と約束。
8. 通期計画の達成可能性。
9. 配当、DOE、自己株式取得、株主優待等の資本政策。
10. 仮説への影響：強化・不変・弱化・破綻。
11. 次回までの観測指標。

必ず「数字は良いか」「質は良いか」「持続可能か」「価格に何が織り込まれているか」を別々に答える。

### ステップ7：保存する

`reports/{会社名}/{会社名}-earnings-{期間}-{YYYYMMDD}.md` に保存する。既存ファイルは上書きしない。

### ステップ8：データ監査

```bash
python tools/report_audit.py --locale ja extract --market jp --report {レポート}
python tools/report_audit.py --locale ja verdict --market jp --results '<照合済みJSON>' --report {レポート名}
```

監査不合格、一次資料未取得、重要数値未照合のいずれかが残る場合はドラフトと明記する。

## 重要原則

- 株価反応で決算の質を判断しない。
- 会社独自指標は定義と過去整合性を確認する。
- 上振れでも一時益や運転資本悪化なら質を下げる。
- 下振れでも先行投資なら回収条件と期限を示す。
- 数字がない箇所を推測で補わない。
