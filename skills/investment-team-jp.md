# 投資調査チーム：4つの役割による並列分析フレームワーク

`$ARGUMENTS` をチームで投資調査・分析する。Teamツールを使用して、実際に複数Agentが並列で調査するチームを作成する。

## 実行手順

### ステップ1：チームの枠組みを提示する

ユーザーに以下のチーム構成を提示し、確認後に開始する：

| 役割 | 責務 | 分析フレームワーク |
|------|------|----------|
| **team-lead**（あなた自身） | 全体調整、総合判断、最終レポートの出力 | 4人の達人を統合したフレームワーク |
| **business-analyst** | ビジネスモデルと経済的な堀の分析 | 段永平の視点 |
| **financial-analyst** | 財務諸表とバリュエーションの分析 | ウォーレン・バフェットの視点 |
| **industry-researcher** | 業界構造と競争状況 | チャーリー・マンガーの視点 |
| **risk-assessor** | リスク評価と経営陣の分析 | 李録の視点 |

### ステップ1.5：AI調査バイアスの評価

チーム作成前に、その企業の「AIによる調査可能性」をユーザーへ提示する：

**情報の豊富さの評価**（調査戦略を決める）：
| 評価 | 特徴 | 調査戦略の調整 |
|------|------|------------|
| A級（情報が豊富） | 上場から長く、証券会社のカバレッジが広い | チームは**反対方向の検証**と**非コンセンサスの視点**を重視し、市場と同じ「正しいが無意味な話」を避ける |
| B級（情報は中程度） | 上場から日が浅く、カバレッジが限定的 | 各Agentの推計データに確信度を付け、team-leadが統合時に「データ充足度」を明記 |
| C級（情報が少ない） | 知名度が低い／新規上場／新興市場 | チームを「第一原理モード」に切り替え、レポートの完全性を求めず、事業の本質に関する中核問題へ集中 |

**重要な注意**：資料が多い ≠ 確実性が高い、資料が少ない ≠ 確実性が低い。AIが出力できる確信度 ≠ 投資の実際の確実性。確実性はビジネスモデルそのものから生まれ、資料の量から生まれるのではない。

評価結果を各Agentへ伝え、調査方法に反映させる。

### ステップ1.75：WebSearch権限の事前確認（重要・Agentの気付かない機能低下を防ぐ）

チームを作成し、バックグラウンドAgentを起動する**前に**、WebSearch権限が許可されていることを必ず確認する。

**事前確認が必要な理由**：このskillは `run_in_background: true` で4つのバックグラウンド子Agentを起動するが、**バックグラウンドAgentはユーザーへ対話形式の権限確認を表示できない**。`WebSearch` が `.claude/settings.local.json` の `permissions.allow` ホワイトリストにない場合、子Agentのオンライン検索は**気付かれないまま遮断**される。その結果、知識の基準日がある学習済み知識だけで回答しながら、フレームワークに沿った「完全に見えるが、実際にはオンライン調査していない」偽の調査へ劣化する。これは本skillで最も危険な失敗パターンである（issue #58を参照）。

**事前確認の手順**：
1. BashでホワイトリストにWebSearchが含まれるか確認する：
   ```bash
   grep -l '"WebSearch"' .claude/settings.local.json ~/.claude/settings.local.json 2>/dev/null
   ```
2. どちらにも一致しない（許可されていない）場合 → **停止し、Agentを起動しない**。ユーザーに次を伝える：
   > ⚠️ WebSearchが権限ホワイトリストにないことを検出しました。バックグラウンド調査Agentはオンライン検索できず、学習済み知識だけによる回答へ劣化します。`.claude/settings.local.json` の `permissions.allow` に `"WebSearch"` を追加する（または `/permissions` で選択する）後、このコマンドを再実行してください。
3. 一致した場合 → 通常どおり続行。

### ステップ2：チームを作成する

TeamCreateでチームを作成する：
- team_name：`{企業名}-research`（英小文字。例：`meituan-research`）
- agent_type：`team-lead`

### ステップ3：4つのタスクを作成する

TaskCreateで以下の4タスクを作成する（各タスクにsubject、description、activeFormを必ず含める）：

#### タスク1：ビジネスモデル分析
- subject：`{企業名}のビジネスモデル、経済的な堀、ユーザー価値を分析`
- descriptionに含める内容：
  1. ビジネスモデルの本質：中核事業の定義、売上高構成の分解
  2. プラットフォーム／製品のフライホイール効果がどう機能するか
  3. 経済的な堀の分析：ブランド／スイッチングコスト／ネットワーク効果／規模の経済／技術的参入障壁を個別に検証
  4. ユーザー／顧客価値：各関係者へどのような独自価値を生み出しているか
  5. 事業ポートフォリオと相乗効果
  6. 段永平の「優れた事業」基準による評価：差別化、価格決定力、持続可能な競争優位性
  7. 最新の決算、業界レポートなどの公開情報を検索

#### タスク2：財務とバリュエーションの分析
- subject：`{企業名}の財務データ、収益力、バリュエーションを分析`
- descriptionに含める内容：
  1. 直近3～5年の売上高、純利益、営業利益の傾向
  2. 収益力指標：自己資本利益率、総資産利益率、粗利率、営業利益率
  3. キャッシュフロー分析：営業キャッシュフロー、フリーキャッシュフロー、設備投資
  4. バランスシートの健全性：現金準備、負債比率、流動性
  5. バリュエーション分析：PER／PSR／PBR／EVなどを、過去および同業他社と比較
  6. 安全余裕の評価：本源的価値 vs 現在の株価
  7. **金融面の厳密な検証（必ずBashでツールを呼び出し、暗算を禁止）**：
     - 時価総額の再計算：`python3 tools/financial_rigor.py verify-market-cap --price {価格} --shares {発行済株式数} --reported {レポート記載の時価総額} --currency {通貨}`
     - バリュエーションの再計算：`python3 tools/financial_rigor.py verify-valuation --price {価格} --eps {EPS} --bvps {1株当たり純資産}`
     - 重要データのクロスチェック：`python3 tools/financial_rigor.py cross-validate --field {項目} --values '{JSON}' --unit {単位}`
     - 3シナリオのバリュエーション：`python3 tools/financial_rigor.py three-scenario --price {価格} --eps {EPS} --shares {発行済株式数・億株} --growth {強気} {中立} {弱気} --pe {強気PER} {中立PER} {弱気PER}`
     - ツールの出力結果を検証記録としてレポートへ直接埋め込む

#### タスク3：業界と競争の分析
- subject：`{業界}の業界構造と{企業名}の競争状況を分析`
- descriptionに含める内容：
  1. 業界の規模と成長：市場規模、成長率、普及率
  2. 競争環境：主要競合の市場シェア、競争戦略の比較
  3. 中核競合の脅威評価：主要競合を個別に分析
  4. 各サブセクターの構造
  5. 業界トレンド：技術変化、政策の影響、新規参入
  6. 産業チェーン分析：上流・中流・下流の価値配分
  7. 最新の業界データと競争動向を検索

#### タスク4：リスクと経営陣の評価
- subject：`{企業名}の投資リスクと経営陣の質を評価`
- descriptionに含める内容：
  1. 経営陣の評価：CEOの能力の輪、誠実さ、戦略眼、資本配分能力、過去の意思決定の質
  2. 規制リスク：現在および潜在的な規制の影響
  3. 競争リスク：各競合の脅威の程度を評価
  4. 事業リスク：新規事業の赤字、拡大の不確実性
  5. マクロリスク：景気循環、業界サイクルの影響
  6. ガバナンス構造：株式所有構造、関連当事者取引、株主還元方針
  7. 長期的な確実性：10年後の企業はどうなるか？ 何がビジネスモデルを破壊し得るか？
  8. 最新の規制動向、経営陣の発言などを検索

### ステップ4：4つの並列Agentを起動する

Taskツールで4つのAgentを同時に起動する（**必ず同一メッセージ内で並列呼び出し**）：

各Agentの設定：
- `subagent_type`：`general-purpose`
- `run_in_background`：`true`
- `team_name`：対応するチーム名
- `name`：対応する役割名（business-analyst / financial-analyst / industry-researcher / risk-assessor）

各Agentのpromptテンプレート：

```
あなたは{企業名}投資調査チームの「{役割の日本語名}」として、{達人名}の投資視点から{企業名}を分析します。

タスク#{タスク番号}：{タスクsubject}を完了してください。

具体的な要件：
{タスクdescriptionの内容}

**調査方法**：
- WebSearchで最新の公開情報（決算、業界レポート、ニュース）を検索
- **財務データは必ず2つの独立した情報源から取得**し、`skills/financial-data.md` の基準に従う（米国株：macrotrends + stockanalysis、香港株：aastocks + macrotrends、中国A株：Eastmoney + CNINFO、台湾株：FinMind `tools/twstock_data.py` + Goodinfo）。2つの情報源の誤差が1%を超える場合は印を付ける
- データの正確性を確保し、重要データに情報源を付記
- 表面的ではなく、深く分析
- **オンライン接続失敗を偽装しない**：WebSearchが遮断／利用不可の場合、学習済み知識をオンライン検索結果に見せかけてはならない。レポート冒頭に「⚠️ 本レポートはオンライン検索できず、学習済み知識（基準日X）に基づくため、確信度を引き下げています」と目立つように記載し、team-leadへ正直に伝え、調査を中止するか判断してもらう

**出力要件**：
- 詳細なレポートとし、重要データはMarkdownの表で示す
- 各分析項目に明確な結論と評価を付ける
- レポート末尾に当該項目の総合結論を記載

**完了後**：
1. TaskUpdateでタスク#{タスク番号}をcompletedに変更
2. SendMessageで完全版分析レポートをteam-leadへ送信（type: "message", recipient: "team-lead"）
```

### ステップ5：レポートを受け取り、進捗を追跡する

- ユーザーに進捗表をリアルタイムで表示（完了したAgent、調査中のAgent）
- レポートを1件受け取るたびに進捗を更新し、そのレポートの中核的な要点を3～5項目表示
- 4件すべてのレポートが揃うまで待つ

### ステップ6：チームメンバーを終了する

すべてのレポートを受け取った後、4つのAgentへshutdown_requestを送信する（SendMessage、type: `shutdown_request` を使用）。

### ステップ7：最終レポートを統合する

4件の分析レポートを統合し、以下の構成で最終レポートを出力する：

---

#### 1. 一文での結論
> 50～100字で、投資に値するかと中核となる投資ロジックを要約

#### 2. 4項目の総合評価表
| 項目 | フレームワーク | 評価（1～5星） | 中核判断 |
|------|------|------------|----------|

総合評価：X / 5

#### 3. 主要データ一覧
重要な財務・事業指標の表（直近2年間を比較）

#### 4. 各項目の分析要約
各項目から最も重要な発見を3～5件抽出

#### 5. 投資仮説（Bull vs Bear）
- 🟢 強気の投資ロジック（5～7項目）
- 🔴 弱気の投資ロジック（5～7項目）

#### 6. ウォーレン・バフェット流購入前チェックリスト
| # | 確認項目 | 合格？ | 説明 |
中核的な10項目を個別に評価

#### 7. 最終投資提案
- 定性判断表（事業の質／経営陣／バリュエーション／タイミング）
- 投資家タイプ別の行動案（積極型／安定型／保守型 → 提案 + 価格レンジ）
- 重要なカタリスト（買い増しシグナル／ポジション縮小シグナルを各3～5件）

#### 8. 要約
100～200字の最終要約

---

### ステップ8：レポートを保存する

完全版の最終レポートを `~/{公司名}投资研究报告_{日期}.md` に保存する（日付形式：YYYYMMDD）。

### ステップ9：データの抜き取り検査（公開判定プロセス）

```bash
# Step 1 — 抜き取り検査リストを抽出（15%を無作為抽出）
python3 tools/report_audit.py extract \
  --report <レポートファイルのパス>

# Step 2 — リストの各項目について信頼できる情報源から数値を取得（skills/financial-data.mdを参照）

# Step 3 — 公開可否の判定を出力
python3 tools/report_audit.py verdict \
  --results '<入力済みJSON>' \
  --report <レポートファイル名>
```

**【公開可】** すべて合格 → レポートを公開可能。**【差し戻し】** 不合格あり → 修正後に再審査。

### ステップ10：チームをクリーンアップする

TeamDeleteでチームのリソースをクリーンアップする。

## 重要な注意事項

1. **4つのAgentは必ず並列で起動**――同一メッセージ内でTaskツールを4回呼び出す
2. **AgentはSendMessageで報告**――ファイル共同作業ではなく、メッセージ通信を使用
3. **データの正確性**――AgentにWebSearchで最新データを検索させ、重要データをクロスチェック
4. **結論を明確にする**――購入／様子見／回避の提案と具体的な価格レンジを曖昧にしない
5. **すべての分析をデータで裏付ける**――情報源を付記
6. **辛抱強く待つ**――4つのAgentによる調査には数分かかるため、ユーザーへ進捗をリアルタイムで更新
7. **反バイアス意識**――team-leadは統合時に、各Agentの分析が資料の豊富さに制約されていないか、市場コンセンサスに過度に収束していないかを評価する。最終レポートには「情報の豊富さの評価」と「AI調査の限界に関する声明」を含める
8. **情報が少ない場合の誠実原則**――推測でフレームワークを埋めて確実性を装うより、「データ不足」と空欄を残す
