# 日本株投資調査チーム：4役並行分析フレームワーク

`$ARGUMENTS` の日本企業をチーム形式で調査する。Team機能を利用できる場合は実際に複数Agentを並行起動し、利用できない場合は4役を順番に実行して各暫定結論を統合前に固定する。

投資対象は東証プライム・スタンダード・グロースの内国普通株に限定する。ETF、REIT、外国株は候補に含めない。海外企業は対象企業の競合、顧客、供給網、技術動向を説明する場合だけ扱い、国外株価や評価倍率を取得しない。

## 実行フロー

### ステップ1：チーム構成を提示する

開始時に次の構成をユーザーへ示す。

| 役割 | 担当 | 分析視点 |
|---|---|---|
| **team-lead** | 全体調整、論点統合、最終レポート | 4視点の統合 |
| **business-analyst** | ビジネスモデル、顧客価値、競争優位 | 段永平の「良い事業」 |
| **financial-analyst** | 財務諸表、資本効率、円建て評価 | バフェットの財務・価格規律 |
| **industry-researcher** | 業界構造、競争、価値獲得 | マンガーの逆向き思考 |
| **risk-assessor** | リスク、経営陣、ガバナンス | 李録の長期確実性 |

### ステップ1.5：AI調査バイアスを評価する

調査前に情報充実度を判定し、全Agentへ伝える。

| 評価 | 特徴 | 調査方針 |
|---|---|---|
| A：情報が豊富 | 上場歴が長く、開示・報道・同業比較が豊富 | 反証と非コンセンサス論点を重視し、市場見解の要約で終わらせない |
| B：情報量が中程度 | 上場歴が短い、事業再編中、開示粒度に偏り | 推定値ごとに根拠と確信度を付け、team-leadがデータ充足度を表示する |
| C：情報が乏しい | 小型、新規上場、ニッチ事業 | 第一原理モードへ切り替え、網羅性より事業の本質と撤回条件を優先する |

資料の多さと投資の確実性を混同しない。AIの情報確信度と、事業・投資結果の確実性は最終レポートで分ける。

### ステップ1.75：検索権限を事前確認する

バックグラウンドAgentを起動する前に、検索機能が利用可能か確認する。Claude CodeでWebSearchを使う場合は、権限設定を確認する。

```bash
grep -l '"WebSearch"' .claude/settings.local.json ~/.claude/settings.local.json 2>/dev/null
```

許可されていない場合はAgentを起動せず、ユーザーへ設定方法を案内する。Codex等で別の検索機能を使う場合は、利用可能なWeb検索へ読み替える。

検索が失敗した場合、学習済み知識を最新情報として装ってはならない。基準日、検索不能、影響範囲を明記し、最新性が必要な判断を停止する。

### ステップ2：チームを作成する

TeamCreateを利用できる場合は次のチームを作る。

- `team_name`: `{会社名ローマ字}-jp-research`
- `agent_type`: `team-lead`

同名チームが存在する場合は上書きせず、既存状態を確認して再利用または日付付き名称にする。

### ステップ3：4つのタスクを作成する

TaskCreateで各タスクに `subject`、`description`、`activeForm` を設定する。

#### タスク1：事業・競争優位

- `subject`: `{会社名}の事業、顧客価値、競争優位を分析する`
- 調査内容：
  1. 誰が、何に、なぜ払い、何が反復するか。
  2. セグメント別売上・利益、数量、単価、継続率、販売経路。
  3. 製品・プラットフォームのフライホイールと相乗効果。
  4. ブランド、切替費用、ネットワーク、規模、コスト、技術、認証、希少資産を個別に検証。
  5. 価格決定力と値上げ後の数量・解約・製品構成。
  6. 増分成長に必要な設備、研究開発、人材、運転資本。
  7. 競争優位を壊す技術、顧客内製化、規制、代替品。

#### タスク2：財務・円建て評価

- `subject`: `{会社名}の財務、資本効率、円建て評価を分析する`
- 調査内容：
  1. 3〜5年の売上高、営業利益、親会社株主帰属利益、EPS。
  2. 粗利益率、営業利益率、ROE、ROIC、増分ROIC。
  3. 営業CF、設備投資、フリーCF、運転資本、株式報酬。
  4. 現預金、有利子負債、リース、年金、政策保有株、非事業資産。
  5. 自己株式控除後株式数、希薄化、自己株式取得・消却。
  6. PER、PBR、EV系倍率、FCF利回り、過去レンジ、国内同業比較。
  7. 強気・基準・弱気の三情景、安全余地、期待収益率。

必ず共通ツールで検算する。

```bash
python tools/financial_rigor.py --locale ja verify-market-cap --price {株価} --shares {自己株式控除後株式数} --reported {時価総額} --currency JPY
python tools/financial_rigor.py --locale ja verify-valuation --price {株価} --eps {EPS} --bvps {BPS} --dividend {年間配当}
python tools/financial_rigor.py --locale ja cross-validate --field {項目} --values '{"有価証券報告書":0,"決算短信":0}' --unit 百万円
python tools/financial_rigor.py --locale ja three-scenario --price {株価} --eps {EPS} --shares {株式数_億株} --growth {強気} {基準} {弱気} --pe {強気PER} {基準PER} {弱気PER} --currency JPY
```

10年終価モデルを使う場合は、調査日の財務省公表値等から円の無リスク金利を確認する。

```bash
python tools/terminal_value.py --locale ja audit --currency JPY --rf {無リスク金利} --r {資本コスト} --roic {定常ROIC} --g {弱気},{基準},{強気}
python tools/terminal_value.py --locale ja irr --profit {終値年利益} --mcap {現在時価総額} --pe {終値PER} --years 10 --payout {配当率等}
```

#### タスク3：業界・競争環境

- `subject`: `{業界}の構造と{会社名}の競争位置を分析する`
- 調査内容：
  1. 国内市場規模、成長率、普及率、更新周期。
  2. 産業チェーンと利益プール、供給制約、交渉力。
  3. 国内主要競合のシェア、戦略、財務余力、価格行動。
  4. 顧客・供給者の集中と内製化・代替リスク。
  5. 技術、政策、規制、人材、電力、物流等の構造変化。
  6. 対象企業が業界成長を利益・CFへ変換できる経路。
  7. 海外企業は事業環境の説明に限定し、投資候補にしない。

#### タスク4：リスク・経営・ガバナンス

- `subject`: `{会社名}の投資リスク、経営陣、ガバナンスを評価する`
- 調査内容：
  1. CEO・経営陣の能力圏、誠実性、戦略、後継計画。
  2. 過去の設備投資、研究開発、買収、売却、負債、還元の成否。
  3. 中期計画の目標と実績、未達説明、開示姿勢。
  4. 規制、景気循環、災害、品質、会計、サイバー等のリスク。
  5. 政策保有株、持合い、親子上場、支配株主、関連当事者取引。
  6. 配当、DOE、自己株式取得、消却、株主優待、増資。
  7. 少数株主保護、取締役会、指名・報酬、特別委員会。
  8. 10年後の事業と、仮説を破壊する事象。

### ステップ4：4 Agentを並行起動する

Task機能を利用できる場合、同じメッセージ内で4 Agentを並行起動する。

- `subagent_type`: `general-purpose`
- `run_in_background`: `true`
- `team_name`: 作成したチーム名
- `name`: `business-analyst` / `financial-analyst` / `industry-researcher` / `risk-assessor`

各Agentのプロンプトには次を含める。

```text
あなたは{会社名}日本株投資調査チームの「{役割名}」です。
タスク #{番号}：{subject} を担当してください。

対象は東証内国普通株で、基準日は{調査日}です。
具体的な調査項目：
{description}

調査規律：
- 会社IR、EDINET、TDnet、JPX、官公庁、国内業界団体を優先する。
- 財務数値は skills/financial-data-jp.md に従い、一次資料と別経路で照合する。
- 価格補助を公式値と表現しない。重要な価格と時価総額は再確認する。
- 事実、推論、未確認事項を分離し、推定値には方法と範囲を付ける。
- 検索不能時は最新情報を推測せず、team-leadへ報告する。
- 海外企業は競合・顧客・供給網の説明に限る。

出力：
- Markdown表を用いた詳細レポート
- 各論点の結論、1〜5点評価、根拠、反証条件
- 最後に総合結論とteam-leadが確認すべき未解決事項

完了後：
1. TaskUpdateでタスクをcompletedにする。
2. SendMessageで完全なレポートをteam-leadへ送る。
```

### ステップ5：レポート受領と進捗管理

- Agent別に未着手・調査中・完了・要確認を表示する。
- 受領ごとに3〜5個の重要発見、データ欠損、他担当との衝突を示す。
- 数値差異を平均して解消せず、期間、単位、会計基準、連結範囲、株式数を照合する。
- 4件が揃う前に最終判断を確定しない。Agentが失敗した場合は再試行条件を示し、代替資料がなければ欠損として進む。

### ステップ6：チームメンバーを終了する

4件を受領後、SendMessageで各Agentへ `shutdown_request` を送り、応答を確認する。

### ステップ7：最終レポートを統合する

#### 1. 一文結論

50〜100字で投資対象としての判断と中核理由を示す。

#### 2. 4領域評価表

| 領域 | 視点 | 評価（1〜5） | 中核判断 | 確信度 |
|---|---|---:|---|---|

#### 3. 基本データ

調査日、証券コード、市場区分、株価、円建て時価総額、会計基準、決算期、主要倍率、配当方針を示す。

#### 4. 各領域の重要発見

各担当から3〜5項目を採用し、共通認識と対立点を分ける。

#### 5. 強気論と弱気論

- 強気材料5〜7項目。
- 弱気材料5〜7項目。
- 最も起こりやすい分析ミス。
- 仮説を破壊する証拠。

#### 6. 買付前チェックリスト

| # | 確認項目 | 合格・条件付き・不合格 | 根拠 |
|---|---|---|---|

事業理解、利益の質、財務耐久性、競争優位、経営者、ガバナンス、評価、機会費用、情報品質、撤回条件を評価する。

#### 7. 三情景と行動表

| 投資家 | 現在の行動 | 価格条件 | 事実条件 | 撤回条件 |
|---|---|---|---|---|

未保有者と既存保有者を分け、買付・追加・保有・縮小・売却を具体化する。個人への売買命令ではなく調査上の判断条件として示す。

#### 8. 総括

100〜200字で、良い会社か、現在価格で良い投資か、何を次に確認するかをまとめる。

最終部に情報充実度、AI分析確信度、投資結果の確実性、未確認事項を置く。

### ステップ8：レポートを保存する

`reports/{会社名}/{会社名}-investment-team-{YYYYMMDD}.md` に保存する。既存ファイルがある場合は上書きせず、内容を確認して日時または版番号を付ける。

### ステップ9：データ監査を実行する

```bash
python tools/report_audit.py --locale ja extract --market jp --report reports/{会社名}/{レポート}.md
python tools/report_audit.py --locale ja verdict --market jp --results '<照合済みJSON>' --report {レポート}.md
```

監査不合格または重要数値の未照合が残る場合は「ドラフト」と明記し、公開可能と判定しない。

### ステップ10：チームを削除する

TeamDeleteでチーム資源を削除する。削除前に全レポートを受領し、未処理メッセージがないことを確認する。

## 重要事項

1. 4 Agentは独立に結論を作り、統合前に相互の結論を見せない。
2. Agent間の連携はSendMessageを使い、同じ成果物を同時編集しない。
3. 最新性が必要な箇所で検索不能なら停止または低信頼化し、偽装しない。
4. 重要数値は二経路で照合し、差異の原因を説明する。
5. 結論は買う・待つ・保有・縮小・見送るの条件を明示する。
6. 資料が少ない場合は空欄を許し、推測で形式を埋めない。
7. 4人の投資家本人を装わず、公開された原則を分析視点として使う。
8. 本プロジェクトは学習・調査目的であり、個別の投資助言ではない。
