# 時代アルファ探索（日本株版）

`$ARGUMENTS` の業界・方向について、**業界認知地図 → 核心質問 → 全面的検証 → 評価の錨 → 保有と転換点**を実行する。狙いは、長期構造変化の中心で、価格決定力と障壁を持ち、同業を継続的に上回る東証内国普通株を見つけることにある。

## 方法の本質

富を運や感情ではなく認識の上に築く。全市場を浅く読むのではなく、指定テーマの2～3の重要工程へ集中する。

1. 範囲を絞る：本当に理解できる工程と企業を少数選ぶ。
2. 高頻度データで補う：決算は遅行するため、月次売上、受注、価格、出荷、稼働、採用等で足元を確認する。
3. 評価の錨を持つ：高成長を理由に価格を無視せず、成功がどこまで織り込まれたかを計算する。

`skills/industry-research-jp.md` は産業全景、`skills/industry-funnel-jp.md` は広い候補の絞り込み、本スキルは時代級の成長線における勝者識別、成長持続性、保有・退出規律に重点を置く。

---

## 第1段階：業界認知地図

対象テーマを物理的・経済的な工程へ分解し、各工程について答える。

1. 導入、成長、成熟、衰退のどこか。普及率と成長率で示す。
2. 誰が誰へ何を売り、どこで粗利と現金が生まれるか。
3. 競争集中度、価格決定権、技術・規模・生態系・許認可の障壁は何か。
4. 売上成長、ROE・ROIC、市場シェアの方向から候補は誰か。

情報源は官公庁、会社IR、有価証券報告書、決算短信、適時開示、業界団体を優先する。二次資料は手掛かりであって結論ではない。

対象企業は東証プライム・スタンダード・グロースの内国普通株に限定する。海外企業は競合、顧客、供給網の比較材料だけに使う。

| 工程 | 段階 | 利益プール | 競争構造 | 東証候補 | 一文の理由 |
|---|---|---|---|---|---|

ここから2～3の重要工程を選び、選定理由と除外理由を記す。

---

## 第2段階：自分で答える三つの核心質問

市場の評判を論拠にせず、第一段階のデータから答える。

1. **最も重要で成長が速い工程はどこか。** 成長率、普及率、受注の可視性で示す。
2. **その工程のアルファ企業はどこか。** 同業より高く安定した粗利、模倣に3年以上かかる障壁、売上とCFが伴う成長を確認する。
3. **なぜ2番手ではなくその企業か。** 両社の差を一文で説明できなければ、未理解とする。

候補は1～3社とする。該当なしも有効な結論である。

---

## 第3段階：五方向の全面検証

| 方向 | 確認事項 |
|---|---|
| 財務 | 直近4～8四半期の売上・利益、粗利、営業CF、受注残、棚卸資産、建設仮勘定 |
| 高頻度データ | 月次売上、出荷、価格、入札、稼働、納期、採用等が決算方向と一致するか |
| 業界 | 政策、技術経路、能力増強、供給過剰、普及率 |
| 競争 | シェア、新規参入、顧客集中、価格交渉力、代替品 |
| 外部環境 | 金利、為替、設備投資循環、規制、災害等の具体的感応度 |

一つでも矛盾する信号があれば、消さずに「何が、なぜ矛盾し、どのデータで決着するか」を書く。

日本企業では、政策保有株、親子上場、支配株主、少数株主保護、資本コスト対応、DOE、自己株式取得・消却も、成長利益が株主へ届くかという観点で確認する。

大規模調査では工程ごとに独立したAgentを並行起動し、各Agentへ「数値、基準日、出典、定義、反証」を返させる。Agentを使えない場合は同じ工程を順番に実行し、未実施を装わない。

---

## 第4段階：評価の錨と介入条件

1. PER、PBR、PSR、FCF利回りの現在値と自社過去分布を確認する。
2. 高倍率を正当化する成長率と持続年数を逆算する。
3. 増分ROIC、再投資余地、自己株式控除後株式数をシナリオへ反映する。
4. 「割安または合理的」「高いが成長で吸収可能」「成功を織り込み過ぎ」の三つに分類する。
5. 一括、分割、価格条件待ちのどれかを、予測ではなく条件として示す。

```bash
python tools/jpstock_data.py quote {証券コード}
python tools/jpstock_data.py financials {証券コード}
python tools/financial_rigor.py --locale ja verify-valuation --price {株価} --eps {EPS} --bvps {BPS} --fcf-per-share {1株FCF}
python tools/financial_rigor.py --locale ja three-scenario --price {株価} --eps {EPS} --shares {株式数_億株} --growth {楽観} {基準} {保守} --pe {楽観PER} {基準PER} {保守PER} --currency JPY
```

重要数値は `skills/financial-data-jp.md` に従い二経路で照合する。

---

## 第5段階：保有規律と転換点

売上・利益の成長、競争構造、普及率、外部条件が仮説内なら、日々の価格変動だけで結論を変えない。一方、次の転換点を企業ごとに観測可能な形で定める。

| 階層 | 信号例 | 観測データ | 頻度 | 閾値 |
|---|---|---|---|---|
| 外部 | 設備投資循環、金利、為替の転換 | 公的統計、会社感応度 | 月次・四半期 | 具体値 |
| 業界 | 供給過剰、価格崩壊、技術代替、普及率頭打ち | 価格、能力、採用 | 月次・四半期 | 具体値 |
| 会社 | 粗利低下、シェア低下、受注鈍化、経営交代 | 決算・開示 | 四半期・随時 | 具体値 |
| 統治 | 大規模希薄化、利益相反、還元方針後退 | TDnet、総会資料 | 随時 | 出来事 |

「転換点」を感覚語にせず、何を、どの頻度で、どの水準まで観測するかを書く。

## 実行と失敗時処理

1. 調査日の基準日を固定する。
2. 認知地図を作り、2～3工程を選ぶ。
3. 候補1～3社の一次資料と高頻度データを取得する。
4. 五方向を交差検証し、矛盾を明記する。
5. 評価と保有・撤回条件を計算する。
6. 情報不足なら候補順位を下げ、分からない項目を列挙する。
7. 保存後に監査する。

```bash
python tools/report_audit.py --locale ja extract --report {レポートパス} --market jp
python tools/report_audit.py --locale ja verdict --results '<照合済みJSON>' --report {レポート名} --market jp
```

監査不合格は公開稿にしない。元資料の期間・単位・連結範囲が違う場合は、無理に平均せず口径差を説明する。

## 報告構造

```text
1. 業界認知地図と重要工程の選定理由
2. 三つの核心質問への回答
3. 候補企業と「なぜこの会社か」
4. 五方向の持続性検証と矛盾信号
5. 評価の錨と介入条件
6. 保有規律と転換点一覧
7. 本分析が誤る三つ以上の経路
8. 情報不足と次回確認日
```

データ密度を優先し、結論を先に作らない。テーマに所属するだけの企業を勝者と呼ばない。
