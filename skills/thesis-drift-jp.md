# 投資仮説のドリフト検出：事実の変化と表現の変化を区別する

`$ARGUMENTS` に投資仮説のドリフト検出を実行する。

**対応する入力形式**：
- `企業名 旧レポートパス 新レポートパス` — 2つの調査レポートまたは投資仮説のスナップショットを指定して比較
- `公司名 reports/{公司名}-thesis-旧日期.md reports/{公司名}-thesis-新日期.md` — 日付付きの2つの投資仮説スナップショットを比較
- `公司名` — `reports/{公司名}-thesis.md` と同じディレクトリの過去スナップショットを自動検索。基準がなければ基準欠落時の処理へ移行

> 「事実が変われば、私は考えを変える。あなたは？」――ケインズ
>
> 「株価変動は投資仮説のドリフトではない。事実が変わったときに初めてドリフトとなる。」――AI Berkshire

## 設計思想

長期保有で最も難しいのは、毎日ニュースを読むことではなく、次の3つを区別することである：
- **事実の変化**：売上高、利益率、競争環境、経営陣の行動、資本配分に検証可能な変化が発生
- **価格の変化**：市場心理またはバリュエーション倍率は変化したが、事業自体は変わっていない
- **表現の変化**：2つのレポートの書き方は異なるが、根底にある証拠と判断は変わっていない

投資仮説のドリフト検出の目的は、**証拠が変化した場合にのみ、投資仮説の変化を認めること**。レポートの表現が変わっただけでドリフトを作り出してはならず、株価の上下だけでファンダメンタルズが変化したと誤認してもならない。

このSkillは、`/thesis-tracker` が出力する構造化項目（中核仮定一覧、レッドライン一覧、バリュエーション基準点、追跡記録表）に依存する。これらの構造がない場合は、先に基準を補い、その後でドリフトを検出する。

## 実行手順

### ステップ1：動作モードを判断する

`$ARGUMENTS` を解析する：
- 2つのレポートパスが指定された場合 → **指定レポート比較**モード
- 企業名だけが指定された場合 → `reports/{公司名}-thesis.md` と過去スナップショットを検索し、**自動スナップショット比較**モード
- レポートが1つしか見つからない、または過去の基準がない場合 → **基準欠落時の処理**モード
- 2つのレポートが同一企業のものでない場合 → 停止してユーザーへ確認を求め、企業をまたぐドリフト判断は行わない

## モードA：指定レポート比較

### A1：2つのレポートを読み込み、検証する

旧レポートと新レポートを読み、以下を抽出する：
- レポート日付、企業名、株式コード
- 中核となる投資仮説（5文）
- 中核仮定一覧
- レッドライン一覧
- バリュエーション基準点
- 追跡記録表
- 経営陣の質に関する判断
- 競争上の経済的な堀に関する判断
- 現在の推奨行動（購入 / 保有 / ウォッチリスト / ポジション縮小 / 全売却）

レポートに重要な構造がない場合は、まず「構造欠落」と明記するが、本文から可能な限り証拠を抽出する。抽出できない項目は「判断不能」とし、結論を捏造しない。

### A2：証拠を正規化する

2つのレポートの事実上の証拠を同じ表へ整理する：

| 項目 | 旧レポートの証拠 | 新レポートの証拠 | データソース | 検証可能か |
|------|-----------|-----------|---------|-----------|
| バリュエーション基準点 | | | | |
| 中核仮定 | | | | |
| レッドライン | | | | |
| 経営陣の質 | | | | |
| 競争上の経済的な堀 | | | | |

**証拠だけを比較し、文体を比較しない。** 新旧レポートが同義の言い換え、順序変更、語調変更にすぎず、事実データと判断閾値が変化していない場合は、Unchangedと判定する。

### A3：数値とバリュエーションを検証する

すべての数値変化は `tools/financial_rigor.py` で正確に計算し、LLMによる暗算を禁止する：

```bash
python3 tools/financial_rigor.py verify-valuation \
  --price {現在の価格} \
  --eps {EPS} \
  --bvps {1株当たり純資産} \
  --fcf-per-share {1株当たりフリーキャッシュフロー}
```

時価総額、変化率、目標株価の差、シナリオ別バリュエーションを計算する場合は以下を使用：

```bash
python3 tools/financial_rigor.py verify-market-cap --price {価格} --shares {発行済株式数} --reported {レポート記載の時価総額} --currency {通貨}
python3 tools/financial_rigor.py cross-validate --field {項目} --values '{JSON}' --unit {単位}
python3 tools/financial_rigor.py three-scenario --price {価格} --eps {EPS} --shares {発行済株式数・億株} --growth {強気} {中立} {弱気} --pe {強気PER} {中立PER} {弱気PER}
python3 tools/financial_rigor.py calc --expr '{正確な計算式}'
```

重要な財務データは、2つ以上の独立した情報源でクロスチェックする。情報源不足、基準の不一致、再検証不能な数値は「確信度が低い / 要確認」と表示する。

### A4：項目別にドリフトを判定する

以下の項目を固定して使用し、臨時に追加・削除しない：

| 項目 | 判断の重点 | Improved | Unchanged | Weakened |
|------|---------|----------|-----------|----------|
| バリュエーション基準点 | 本源的価値、PER／PBR／フリーキャッシュフロー利回り、安全余裕、目標株価レンジ | 安全余裕が拡大、または本源的価値を上方修正しツールで検証済み | バリュエーションレンジと安全余裕に実質変化なし | 安全余裕が縮小、本源的価値を下方修正、またはバリュエーション仮定が無効化 |
| 中核仮定一覧 | 売上高成長率、利益率、キャッシュフロー、ユーザー／受注／生産能力など検証可能な仮定 | より多くの仮定が新たな証拠で強化 | 仮定の状態と証拠がおおむね一致 | 仮定が限界的に弱化、毀損、または崩壊 |
| レッドライン一覧 | 誠実性、規制、事業衰退、競合の突破、経営陣の異常行動 | 既存のレッドライン・リスクが解消または大幅低下 | 未発動でリスク水準も不変 | レッドラインが発動、または発動確率が上昇 |
| 経営陣の質 | 誠実性、資本配分、自社株買い・配当、実行力、株主重視 | 新たな行動で信頼度が向上 | 行動が従来の判断と一致 | 行動が信頼を損ない、または資本配分が悪化 |
| 競争上の経済的な堀 | 市場シェア、価格決定力、ネットワーク効果、コスト優位性、代替の脅威 | 経済的な堀が広がる、または競争優位性が検証される | 競争環境に実質変化なし | 経済的な堀が弱まり、または競合が突破 |

各項目の結論は、**Improved / Unchanged / Weakened** の3種類に限定する。

### A5：証拠主導のルール

Unchanged以外の結論には、変化を生じさせた具体的な新証拠を必ず引用する：
- 決算項目：売上高成長率、粗利率、営業キャッシュフロー、自社株買い額、ネットキャッシュなど
- 規制開示：10-K／20-F、年次報告書、中間報告書、香港取引所の開示、SEC filingなど
- ニュースイベント：経営陣の変更、規制処分、重大顧客の喪失、競合製品の突破
- 価格とバリュエーション：「バリュエーションの変化」か「ファンダメンタルズの変化」かを明記し、混同しない

変化を説明できる証拠が見つからない場合は、**Unchanged** または **判断不能** とし、表現の違いからドリフトを推定してはならない。

### A6：ドリフトレポートを出力する

#### レポート構成

```
1. 比較対象と期間
2. 総合結論：投資仮説はドリフトしたか
3. 項目別ドリフト表
4. 証拠の差異の詳細
5. バリュエーションと数値の再計算
6. 推奨行動の変化
7. 不確実な項目と追加が必要な情報源
8. 次回の追跡重点項目
```

#### 項目別ドリフト表

| 項目 | 旧判断 | 新判断 | ドリフト方向 | 発動証拠 | 確信度 |
|------|-------|-------|:--------:|---------|:------:|
| バリュエーション基準点 | | | Improved / Unchanged / Weakened | | 高／中／低 |
| 中核仮定一覧 | | | Improved / Unchanged / Weakened | | 高／中／低 |
| レッドライン一覧 | | | Improved / Unchanged / Weakened | | 高／中／低 |
| 経営陣の質 | | | Improved / Unchanged / Weakened | | 高／中／低 |
| 競争上の経済的な堀 | | | Improved / Unchanged / Weakened | | 高／中／低 |

**Unchangedの行では発動証拠を `—` とし、表を埋めるために証拠を捏造しない。**

#### 総合結論で必ず答えること

1. **投資仮説はドリフトしたか？** ドリフトなし / 正方向のドリフト / 負方向のドリフト / 証拠不足で判断不能
2. **ドリフトはどこから生じたか？** バリュエーション / ファンダメンタルズ / 経営陣 / 競争環境 / レッドライン・イベント
3. **事実の変化か、価格の変化か？** 明確に分けて説明
4. **推奨行動はどう変化するか？** 例：Watch → Buy、Buy → Hold、Hold → Reduce、Reduce → Exit
5. **次に必要な証拠は何か？** 次回決算 / 規制開示 / 経営陣の説明 / 競合データ

## モードB：自動スナップショット比較

### B1：スナップショットを検索する

`reports/` 内で以下を検索：
- `reports/{公司名}-thesis.md`
- `reports/{公司名}-thesis-*.md`
- `reports/{公司名}/` ディレクトリ内で `thesis`、`论文`、`追踪` を含むレポート

最も古く、かつ構造が完全なファイルを旧レポート、最新のファイルを新レポートとして選ぶ。ユーザーが日付を指定した場合は、その指定を優先する。

### B2：誤った組み合わせを防止する

比較前に必ず確認する：
- 企業名または株式コードが一致
- レポート日付が異なる
- 2つのレポートから投資仮説の構造または調査結論を抽出可能

同一企業であることを確認できない場合は停止し、明確なパスをユーザーに求める。

### B3：モードAを実行する

有効な2つのスナップショットを見つけた後、モードAを完全に実行する。

## モードC：基準が欠落している場合

レポートが1つしか見つからない、または旧スナップショットがない場合：

1. 明確に説明：**比較可能な過去の基準がないため、ドリフト検出を実行できない**
2. 記憶や市場の印象に基づいて過去の投資仮説を作らない
3. まず `/thesis-tracker {企業名} 投資仮説を作成` で構造化した基準を作るよう案内
4. 現在のレポートが十分に完全なら、将来のドリフト検出基準として `reports/{公司名}-thesis.md` に保存するよう提案可能

出力形式：

```
投資仮説のドリフト検出を実行できません：過去の基準がありません。

検出結果：
- 現在のレポート：{パス / 見つからない}
- 過去の基準：見つからない

提案：
1. 先に /thesis-tracker {企業名} 投資仮説を作成 を実行
2. 次回の決算または重大イベント後に、/thesis-drift {企業名} 旧レポート 新レポート を実行
```

## 重要原則

- **表現より証拠を優先**――同義の言い換えはドリフトではない。事実上の証拠が変化した場合だけドリフトとなる
- **株価よりファンダメンタルズを優先**――株価の上下が影響するのはバリュエーション基準点であり、事業の質を自動的に変えるものではない
- **数値は必ず再計算**――すべての比率、バリュエーション倍率、目標株価の差は `tools/financial_rigor.py` を使用
- **不確実な場合は不確実と記載**――情報源不足、基準不一致、再検証不能の場合は無理に判定しない
- **レッドラインは別枠で扱う**――レッドラインの発動は割安なバリュエーションより優先し、低いPERで覆してはならない
- **出力を後から検証可能にする**――Improved／Weakenedの各結論は、具体的な証拠へ遡れるようにする
