# 投資調査：ウォーレン・バフェット／チャーリー・マンガー／段永平／李録による統合分析フレームワーク

## 日本語版の共通実行ルール

- 株価、時価総額、財務数値、バリュエーションなどの通貨単位は、日本株では円（JPY）、米国株では米ドル（USD）を使用する。市場横断比較で換算する場合は、元の通貨を併記し、換算日と為替レートを明示する。
- レポートを保存・更新・検索する場合は、`reports/` ではなく `reports-jp/` 配下を使用する。
- データ取得・計算・検証には必要に応じて `tools/` の既存ツールを使用する。日本株では `python tools/jpstock_data.py quote {証券コード}` で株価、`financials` / `filings` でEDINETの財務・開示資料を取得し、重要数値は `tools/financial_rigor.py`、完成レポートは `tools/report_audit.py` で検証する。
- 競合・産業チェーンの調査では、日本・韓国・台湾・欧州・中国・米国など世界の関連企業を、上場市場や資料言語を理由に除外しない。ただし、特定の海外市場に固有のデータ取得手順、評価基準、通貨例は設けず、各社の公式IR・法定開示・取引所資料を優先する。

`$ARGUMENTS` を体系的に投資調査・分析する。

## 調査フレームワーク

ウォーレン・バフェット、チャーリー・マンガー、段永平、李録という4人の投資家の方法論に基づき、以下の7モジュールを順番に実行する：

### 事前ステップ：AI調査バイアスの自覚（必須）

調査開始前に、その企業の「AIによる調査可能性」を評価し、潜在的なデータバイアスを特定する：

**情報の豊富さの評価**：
| 評価 | 特徴 | AI調査の罠 | 対応戦略 |
|------|------|-----------|---------|
| A級（情報が豊富） | 上場から長く、証券会社のカバレッジと報道が多い | コンセンサスが強すぎ、AIの出力が市場価格に織り込まれた見方へ収束し、アルファが限定的 | 反対方向の検証を重視：賢い投資家が買わない理由は？ 見落とされたリスクは？ |
| B級（情報は中程度） | 上場1～3年、カバレッジが限定的、一部データに推計が必要 | AIが空白を「妥当な推測」で埋め、完全に見えるが実際には偽の確実性を作る可能性 | 各推計データに確信度を付け、「根拠ある推計」と「根拠のない補完」を区別 |
| C級（情報が少ない） | 新規上場／知名度の低い銘柄／新興市場で、ほぼカバレッジなし | AIが資料不足を理由に過度に保守的となり、「不明 = 悪い」と誤認 | 第一原理による問い（下記参照）を使い、限られた情報から事業の本質を抽出 |

**C級企業の第一原理による調査方法**：
公開情報が不足する場合、「完全に見える」レポートをつなぎ合わせようとせず、次の根底にある問いへ集中する：
1. 顧客は誰か？ なぜ支払うのか？ 代替手段はあるか？
2. 再購入を促す要因は何か？ 習慣、ロックイン、それとも新たな価値の継続的創出か？
3. 競合が十分な資本を持てば、この事業を再現できるか？
4. 経営陣はどのような重要な意思決定をしてきたか？ それはどのような判断力と価値観を示すか？

**バイアスの自己点検リスト**（調査全体を通じて警戒）：
- [ ] 「確実だ」という感覚は事業の本質から来ているか、資料の量から来ているか？
- [ ] この企業の資料が半分になった場合、結論は変わるか？
- [ ] AIの分析は市場コンセンサスと酷似していないか？ そうなら、自分の情報優位性はどこにあるか？
- [ ] 「公開情報は少ないが、事業の本質が極めて優れている」可能性を過小評価していないか？

情報の豊富さの評価をレポート冒頭に記載し、最終結論で「AI調査の確信度」と「実際の投資の確実性」の違いを明記する。

### ステップ1：データ収集

> **データソース基準**：`skills/financial-data-jp.md` を参照。すべての財務データは2つの独立した情報源から取得し、誤差が1%を超える場合は印を付ける。
> - 日本株：EDINET／TDnet／企業IRを正本とし、`tools/jpstock_data.py` の価格データで補完
> - 米国株：SEC EDGAR／企業IRを正本とし、独立した第三者情報源で補完

TaskツールでバックグラウンドAgentを起動し、オンラインで以下のデータを収集する：

1. 売上高構成：直近会計年度および直近4四半期のセグメント別売上高、成長率、粗利率
2. 財務指標：直近5年間の売上高、純利益、粗利率、営業利益率、フリーキャッシュフロー、現金準備
3. 競争環境：市場シェア、主要競合との比較
4. ビジネスモデルと経済的な堀：競争優位性の中核となる源泉
5. 技術力：中核技術スタック、研究開発投資
6. 経営陣：創業者／CEOの経歴、持株比率、重要な意思決定の実績
7. 業界見通し：TAM（獲得可能な最大市場規模）、成長予測
8. リスク要因：地政学、規制、サプライチェーンなど
9. 現在のバリュエーション：時価総額、PER、PSR、PEG、EV/Revenue
10. 強気・弱気双方の中核的な論点

#### データのクロスチェック（必須。金融厳密性ツールを使用）

データ収集後、**`tools/financial_rigor.py` を必ず呼び出して、重要データをプログラムで検証する**。LLMの暗算による誤差を排除する。

**必ず検証するデータ項目**：
- 発行済株式総数（取引所、Yahoo Finance、StockAnalysisなど2つ以上の情報源で確認）
- 現在の株価と時価総額（**株価 × 発行済株式総数を手動計算し、レポート記載の時価総額と比較して単位誤りを防ぐ**）
- 直近会計年度の売上高と純利益（企業の年次報告書 + 第三者情報源1つ以上で確認）
- 現金準備とネットキャッシュ（現金 + 短期投資 - 負債総額。基準の違いに注意）
- 経営陣の持株比率（経済的持分と議決権を区別し、複数議決権構造に注意）

**強制検証手順（Bashでツールを呼び出す）**：

Step 1 — 時価総額の再計算（浮動小数点ではなく正確な10進数）：
```bash
python3 tools/financial_rigor.py verify-market-cap \
  --price {株価} --shares {発行済株式総数} --reported {レポート記載の時価総額} --currency {通貨}
```

Step 2 — 重要データを複数情報源でクロスチェック：
```bash
python3 tools/financial_rigor.py cross-validate \
  --field {項目名} --values '{"情報源1": 数値, "情報源2": 数値}' --unit {単位}
```
売上高、純利益、現金準備について個別に実行する。

Step 3 — バリュエーション指標を正確に再計算（PER／PBR／自己資本利益率／フリーキャッシュフロー利回りなど）：
```bash
python3 tools/financial_rigor.py verify-valuation \
  --price {株価} --eps {EPS} --bvps {1株当たり純資産} --fcf-per-share {1株当たりFCF} --dividend {1株当たり配当}
```

**検証ルール**：
1. 各重要データ項目に2つ以上の独立した情報源を使用
2. 情報源間で差異がある場合は、企業の年次報告書／取引所データを優先し、差異の理由を明記
3. **計算を伴うデータはすべてツールで再計算し、LLMによる暗算を禁止**
4. ツールの出力結果を、レポート付録「重要データのクロスチェック記録」へ直接埋め込む
5. ツールが「❌ 偏差が大きすぎる」と報告した場合、原因を調査するまで分析を続行しない

**よくある誤りの防止**：
- 時価総額の単位：円と米ドル、億と百万・十億を混同し、ゼロを不足／過剰にする誤りが起きやすい
- フリーキャッシュフローの基準：設備投資の定義が情報源により異なる場合がある（リース、買収などを含むか）
- 負債の基準：オペレーティング・リース負債を含むか
- 持株比率：複数議決権企業では経済的持分 ≠ 議決権

### ステップ2：事業の本質の分析 — 段永平の「正しい事業」

分析項目：

- **段永平流の追加質問**：この事業の優れた点は何か？ 一文だけで表すなら何か？

- 3シナリオのバリュエーション――**必ずツールで正確に計算し、暗算を禁止**：
```bash

  --growth {強気の成長率} {中立の成長率} {弱気の成長率} \
  --pe {強気PER} {中立PER} {弱気PER} --years 3 --currency {通貨}
```
- 自社の過去のバリュエーションと比較
- 同業他社のバリュエーションと比較

#### 長期割引バリュエーション（10年間。必須）

3年間の3シナリオは「割高か」を答え、10年間の割引は「集中投資に値するか」を答える。**10年間のIRRまたはターミナル倍率を示す調査は、必ずこのプロセスを通り**、`tools/terminal_value.py` を使用する。

ターミナル倍率の正当な算出元は永久成長モデルだけであり、**同業比較を使ってはならない**：

$$PER_{ターミナル} = \frac{1 - g/ROIC}{r - g}$$

> 「同業他社が13倍だから対象企業は16倍」は循環論法になり得る。他社の現在の価格を使って、自分が仮定した価格の妥当性を証明してはならない。現在の市場全体が割高なら、類似企業法はその割高さを10年後へそのまま移す。

**Step 1 — 3つの入力を定め、それぞれ理由を記載する（ここはすべて判断であり、計算ではない。レポートで必ず説明する）：**

| 入力 | 決め方 | よくある誤り |
|---|---|---|
| **r** 資本コスト | 無リスク金利 + β × ERP。**通貨はキャッシュフローと一致させる**。日本株は円建て、米国株は米ドル建ての金利とERPを同じ基準日で使う | 現在の低い国債利回りだけに追随し、事業リスクを過小評価する |
| **ROIC** 定常状態の増分投下資本利益率 | 既存事業のROIC（計上されない無形の経済的な堀を含むため高め）と、配当から逆算した暗黙の増分ROIC（設備投資のリターンをゼロと仮定するため低め）の間に置く | 既存事業のROICをそのまま使用し、新たな追加投資も同じリターンを再現できると仮定する |
| **g** 永久成長率 | **今後10年間の成長率ではない**（それはターミナル年の利益に反映済み）。ターミナル年以降、永久に続く成長率であり、当該通貨圏の長期名目成長率を上限の目安にする | キャッシュフローと異なる通貨圏のrとgを組み合わせる |

**gはrに合わせて変えない**――gはターミナル年以降の経済に関する判断、rは要求リターンであり、独立した2つの事項である。感応度分析ではrだけを動かす。

**Step 2 — 3つの強制公開チェック（不合格ならバリュエーションをレポートに記載してはならない）：**

```bash
python3 tools/terminal_value.py audit \
  --currency {JPY|USD} --r {資本コスト} --roic {定常ROIC} \
  --g {弱気g},{基準g},{強気g} --rf {無リスク金利} --beta 1.0 \
  --discrete-risks "{リスク名}:{シナリオ|テールケース|確率|未モデル化},..."
```

3つのチェック内容と差し戻し条件：

| # | チェック | 差し戻し条件 |
|---|---|---|
| **C1** | **rとgは同じ通貨でなければならない** | rが別通貨のレンジにある、または基準ケースのgが当該通貨の上限を超える。ツールは「これはUSDの水準――rは自国通貨、gは外貨を使用」と直接指摘する |
| **C2** | **分母r−gが5パーセントポイント以上** | いずれかのケースで5ポイント未満。分母が狭いほどgの小さな変化でバリュエーションが激変し、分母が0以下ならモデルは無効。上方／下方シナリオを作る必要がある場合は `--upside-only` で明示するが、レポートに「これはシナリオであり、バリュエーションではない」と記載する |
| **C3** | **離散リスクをrまたはβへ含めない** | リスクの帰属を `割引率`／`r`／`beta` とした場合はすべて差し戻す。上場廃止、VIE無効化、地政学的な供給停止、重大な規制措置は `シナリオ` または `テールケース` に分類する。βが1.0から外れる場合は `--beta-justification` が必須 |

**C3を強制する理由**：rを3ポイント引き上げた場合、第10年のキャッシュフローへの罰は第1年の2.6倍になる。一方、上場廃止リスクはおおむね均等、または初期に偏る年間ハザード率である。**離散リスクを割引率で処理すると、リスクの時間分布を体系的に逆転させる。** 正しくはテールシナリオを別に設け、確率を付ける。

**Step 3 — 数値を出す（公開可となった後にのみ実行）：**

```bash
# 単一点の売却時PER。完全な計算式を表示（内部留保率/分子/分母を展開し、レポートで引用可能にする）
```

## 出力要件

1. すべての分析はデータで裏付け、情報源を付記する
2. 重要データはMarkdownの表で示す
3. 各モジュールの末尾に、対応する達人の「追加質問」を必ず置く

5. 結論を明確にし、購入／様子見／回避の提案を曖昧にしない
6. バリュエーション部分に具体的な価格レンジを含める
7. **レポート冒頭**に「情報の豊富さの評価」（A／B／C）と「AI調査の限界に関する声明」を必ず含める
8. **レポート末尾**で「AI分析の確信度」と「投資の確実性」を区別する。前者は資料量、後者は事業の本質によって決まる。本レポートのどの結論が十分なデータに基づき、どれが限られた情報からの推論かを明確に伝える

## データの抜き取り検査（公開判定プロセス）

レポートをファイルへ保存後、データの抜き取り検査を**必ず**実行し、合格後にのみ公開する：

**Step 1 — 抜き取り検査リストを抽出（15%を無作為抽出）：**
```bash
python3 tools/report_audit.py extract \
  --report <レポートファイルのパス>
```
`fetched_value`（入力待ち）を含むJSONテンプレートを出力する。

**Step 2 — 数値を取得して検証：**
リスト内の各データについて、`skills/financial-data-jp.md` の基準に従い、信頼できる情報源から数値を取得する
（日本株：EDINET／TDnet／企業IR、米国株：SEC EDGAR／企業IRを中心に、独立した第三者情報源で補完）。
`fetched_value`／`fetched_source`／`fetched_value2`／`fetched_source2` を入力する。

**Step 3 — 判定を出力：**
```bash
python3 tools/report_audit.py verdict \
  --results '<入力済みJSON>' \
  --report <レポートファイル名>
```

- **【公開可】**：すべての抜き取り項目の偏差が1%以下 → レポートを公開可能
- **【差し戻し】**：いずれかの偏差が1%超 → 該当データを修正後に再検査し、公開可となるまで繰り返す

**Step 4 — バリュエーション基準の再検査（10年間の割引バリュエーションを含むレポートでは必須）：**

レポートに10年間のIRRまたはターミナル倍率が含まれる場合、最終稿で使用したパラメータをもう一度auditに通し、レポートの数値が公開判定時と一致することを確認する：

```bash
python3 tools/terminal_value.py audit \
  --currency {通貨} --r {r} --roic {ROIC} --g {3ケースのg} --rf {無リスク金利} \
  --beta {β} --discrete-risks "{リスク帰属一覧}"
```

- **【公開可】**（終了コード0）→ レポートを公開可能
- **【差し戻し】**（終了コード1）→ 修正後に再実行し、公開可となるまで繰り返す

**このステップを省略できない理由**：ステップ7のauditは計算前に行うが、レポート執筆中にgまたはrを再調整することが多い。**公開前の最後のauditこそ、レポートに責任を持つための検査である。**
