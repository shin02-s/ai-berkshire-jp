# 「会社を読み解く」深掘り連載（日本株版）

`$ARGUMENTS` の日本上場企業について、3～8本の長編記事からなる公開向けシリーズを作る。文章量ではなく、**事実を厳密に直せること**を品質の中心に置く。

対象は東証プライム・スタンダード・グロースの内国普通株。海外企業は競合、顧客、供給網、技術動向を説明するときだけ言及し、投資対象や評価対象にはしない。

---

## 1. 適用場面

一社を事業、競争優位、財務、経営、資本配分、評価、売却条件まで一貫して理解し、公開できる連載にするときに使う。

- 各回は単独で読めるが、全回で同じ判断軸と数値口径を共有する。
- 想定読者は、時間をかけて一社を理解したい個人投資家。
- 単発の企業分析は `skills/investment-research-jp.md`、決算速報は `skills/earnings-review-jp.md`、業界分析は `skills/industry-research-jp.md` を使う。

---

## 2. 本数を先に決める

8本を固定しない。独立した「鋭い問い」が何本あるかで3～8本を選ぶ。

| 複雑度 | 特徴 | 本数 |
|---|---|---:|
| 高 | 複数事業、上場子会社・投資資産、長い経営史 | 7～8 |
| 中 | 2～3事業と大きな構造変化 | 4～6 |
| 低 | 主業が明快で論点が集中 | 3 |

3本構成の標準例：

1. 認識の修正、事業の本質、競争優位
2. 最大の変数、隠れた資産、構造変化
3. 財務、経営、評価、売却条件

同じ事実の言い換えで量を埋め始めたら統合する。1本が12,000字を超えて論点が二つあるなら分割する。`00-シリーズ案内.md` を索引として置くが、公開記事には数えない。

---

## 3. 8つの主軸

複雑な企業では次の全主軸を使い、単純な企業では漏れ確認のチェックリストとして3～6本に畳み込む。

| # | 題名の方向 | 中心となる問い | 目安字数 |
|---:|---|---|---:|
| 01 | あなたは本当にXを理解しているか | 三つの誤解を一次資料で崩す | 4,000～5,000 |
| 02 | Xの競争優位は何か | 5年後、10年後も残るか | 6,000～8,000 |
| 03 | 最大の利益源 | 何が利益を生み、なぜ続くか | 6,000～8,000 |
| 04 | 帳簿に隠れた別の価値 | 上場子会社、非上場持分、政策保有株、遊休資産 | 8,000～10,000 |
| 05 | 構造変化の勝者か敗者か | 技術・制度・人口動態が事業別に与える影響 | 8,000～10,000 |
| 06 | 有価証券報告書を価値投資で読む | 粗利、営業利益、FCF、ROE、株式数 | 8,000～10,000 |
| 07 | 経営を任せられるか | 誠実さ、資本配分、後継、統治 | 8,000～10,000 |
| 08 | いくらなら買い、何で見直すか | 分解評価、三情景、赤線、保有判断 | 10,000～12,000 |

独立した内容がない主軸は削るか統合し、その会社固有の論点に置き換える。

---

## 4. 各回の共通骨格

- 冒頭引用：`> 「Xを読み解く」第0N回・{主軸}` と読了時間。
- 第一節：背景説明ではなく、反直感的な数値、曲線、または市場の懸念から始める。
- 本文：事実、解釈、反証を明確に分ける。
- 終盤：`## 今回の要点` を5～8項目。本文の数値と完全に一致させる。
- 最後：`## 次回予告`。鋭い問いだけを示し、答えは先に書かない。
- 末尾：シリーズ番号と「公開情報に基づく調査であり、投資助言ではない」旨を斜体で記す。

### 回ごとの専用骨格

#### 01 認識の修正

株価や評価の定義が変わった履歴、三つの典型的な誤解、財務数値による反証、シリーズ全体の読み方、結論を伏せた評価上の問い。

#### 02 競争優位

挑戦者の事例と年、顧客が移れない理由、規模・学習・販売・ブランドの循環、5年後と10年後の劣化条件、「十分な資本があれば再現できるか」という逆思考。

#### 03 利益源

意外な利益構成、価格決定力、シェアと数量の成長余地、主張が崩れる条件、再現可能な組織能力、市場が見落とす理由、構造変化の影響。

#### 04 隠れた価値

連結対象と持分法・その他投資を分けた資産表、会計処理、保有目的、政策保有株、親子上場、持合い、少数株主保護、資産価値の割引理由。**連結済み子会社を別価値として二重計上しない。**

#### 05 構造変化

市場が懸念する数値、事業別の勝敗、代替される経路、5～10年の複数シナリオ、今後1年の監視信号。会社全体を一語で勝者・敗者にしない。

#### 06 財務

利益率の変化要因、日本基準／IFRSの口径、営業利益と親会社株主に帰属する利益、自己株式控除後の一株指標、貸借対照表、FCF、ROE、資本配分、相対・過去評価、10項目チェック、三文要約。

#### 07 経営

主要人物、具体的な意思決定、持株・報酬、実際の危機における誠実さ、過去5年の約束と実績、買収・売却・配当・DOE・自己株式取得と消却、政策保有株の縮減、後継者、支配株主と少数株主の利害。

#### 08 意思決定

事業別評価、ネットキャッシュ、非事業資産の分離、過去倍率は将来を保証しないという警告、楽観・基準・保守の利益シナリオ、暗黙の成長率、見直しの赤線、確率ではなく赔率で結ぶ。

```bash
python tools/financial_rigor.py --locale ja three-scenario --currency JPY ...
python tools/terminal_value.py --locale ja audit --currency JPY --rf {調査日当日の財務省公表値} ...
```

終価計算では `r > g`、最低スプレッド、円建ての同一口径を確認する。JPYでは無リスク金利を埋め込まず、調査日の公表値を必ず渡す。

## 5. 文章の基準

### 語り口

- 最初の一文に数値または反直感的な結論を置く。
- 先に事実、次に論理、最後に結論を書く。
- 核心判断には反対側の証拠を併記する。
- 名言を並べず、価値投資の考え方を具体的な判断に使う。
- スマートフォンの冒頭表示だけでも意味が通る見出しにする。

### 避ける語

| 避ける表現 | 置き換え |
|---|---|
| 明らか、必ず、絶対 | データが示す、現時点の証拠では |
| 私は思う | 本稿の基準では、または削除 |
| 完璧、教科書的、神業 | 具体的な事実を記述 |
| 大幅に割安 | どの前提で何%の差か示す |

題名は反差のある数字や反共識の結論を使えるが、扇情的な比喩や「誰々版X」は避ける。

---

## 6. 厳格な事実確認

### 書く前に警戒する疑似精密さ

1. 主観確率を掛けた期待収益は出さない。シナリオ、条件、方向を分ける。
2. 第三者推計の利用者数・シェアは定義差を確認し、二つの信頼できる基準値に限定する。
3. 過去年率をそのまま将来へ延長しない。高低レンジと成立条件を示す。
4. 非開示の持分比率や顧客比率を一点推定しない。範囲または不明とする。
5. 競合の失敗を単一原因へ強引に帰属させない。

### 修訂時の7項目

```text
□ 1. 時価総額、利益、持分比率、株式数が全回で一致する
□ 2. 日本基準／IFRS、連結／単体、調整後指標、FCFの定義が明記される
□ 3. 連結子会社、持分法、政策保有株、自己株式を二重計上していない
□ 4. 同業比較の分子・分母、現金控除、会計期間が公平である
□ 5. 主観的な確率加重値を削除した
□ 6. 絶対表現と過度な賛辞を弱めた
□ 7. 一次資料以外のデータに出典と基準日を付けた
```

財務数値はEDINET、有価証券報告書、決算短信、会社IR、TDnetを優先し、重要数値は独立した第二経路でも照合する。価格補助にyfinanceを使う場合は非公式と明示する。

```bash
python tools/jpstock_data.py financials {証券コード}
python tools/financial_rigor.py --locale ja cross-validate --field {項目} --values '{ソース別JSON}' --unit {円単位}
python tools/report_audit.py --locale ja extract --report {記事パス} --market jp
python tools/report_audit.py --locale ja verdict --results '<照合済みJSON>' --report {記事名} --market jp
```

## 7. 実行フロー

### 段階1：調査

1. 直近5年の有価証券報告書、決算短信、適時開示、統合報告書を読む。
2. 独立した調査資料を最低3件読み、合意と反対意見を分ける。
3. `skills/investment-team-jp.md` または `skills/investment-research-jp.md` で内部底稿を作る。
4. 全主軸を確認し、3～8本の構成と各回の核心命題を確定する。

### 段階2：順番に執筆

01から順に書き、途中を飛ばさない。各回を次へ保存する。

`reports/{会社名}/「{会社名}を読み解く」/0X-{短い題名}.md`

同名フォルダがすでにある場合は上書きも混在もさせず、`「{会社名}を読み解く」-{YYYYMMDD}/` を作る。旧版は変更しない。各回を利用者が確認するまで外部公開やGitへの送信は行わない。

### 段階3：全回の整合性検査

利用可能な複数Agentで記事群を並行確認する。

1. 同じ数値が全回で一致するか。
2. 専門用語が初出で説明されているか。
3. 「第6回参照」等の相互参照が実在するか。
4. 本文と要点欄の数字が一致するか。
5. 評価基準日と株価基準日が一致するか。

Agentを利用できない場合は同じ観点を順番に確認し、未実施と偽らない。

### 段階4：公開前検査

全記事へ監査を実行し、個人名、端末の利用者名、絶対パス、未公開持株情報、社内情報がないか検索する。監査不合格なら公開稿とせず、修正後に再監査する。外部公開、commit、pushは利用者が明示的に求めた場合だけ行う。

## 8. 修訂意見の扱い

### 8.1 先に事実を確認する

数値が違うと指摘されたら、直ちに置換せず、「指摘値」「一次資料の値」「記事で使用した値」を並べ、期末、会計基準、連結範囲、自己株式、単位の違いを確認する。

### 8.2 修訂の等級

| 等級 | 内容 | 対応 |
|---|---|---|
| 重大 | 数字、帰属、会計口径の誤り | 必ず直す |
| 主観 | 絶対表現、過度な賛辞、扇情的比喩 | 弱めるか削る |
| 粒度 | 出典、定義、注記不足 | 読みやすさを保って補う |
| 不確実 | 第三者推計の差が大きい | 一点修正より削除または範囲化 |

### 8.3 連動修訂

- 時価総額を直したらPER、PSR、FCF利回り、割引率を全回で再計算する。
- 持分比率を直したら資産順位、評価、売却可能性を直す。
- 株式数を直したらEPS、自己株式取得効果、希薄化を直す。
- 用語定義を直したら初出、後続参照、要点欄を直す。

修訂後は、変更箇所、連動修正、残る未確認点を表にして報告する。

---

## 9. このスキルがしないこと

- 読者の代わりに投資判断を確定しない。
- 株価を一点予測しない。条件付きシナリオを示す。
- 主観確率による期待年率を計算しない。
- 著名人の保有を投資根拠にしない。
- 内容がないのに8本へ水増ししない。
- 未公開情報や利用者の個人情報を使わない。

## 10. 品質原則

この連載の価値は、文章の華やかさではなく、一次資料、口径、反証、連動修訂を最後まで守ることにある。確認できない数字は削るか不明とし、読みやすさのために真実性を犠牲にしない。
