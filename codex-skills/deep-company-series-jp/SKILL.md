# XX社を理解する（企業深掘りシリーズ）：3～8本の長文で1社を分解する

## 日本語版の共通実行ルール

- 株価、時価総額、財務数値、バリュエーションなどの通貨単位は、日本株では円（JPY）、米国株では米ドル（USD）を使用する。市場横断比較で換算する場合は、元の通貨を併記し、換算日と為替レートを明示する。
- レポートを保存・更新・検索する場合は、`reports/` ではなく `reports-jp/` 配下を使用する。
- データ取得・計算・検証には必要に応じて `tools/` の既存ツールを使用する。日本株では `python tools/jpstock_data.py quote {証券コード}` で株価、`financials` / `filings` でEDINETの財務・開示資料を取得し、重要数値は `tools/financial_rigor.py`、完成レポートは `tools/report_audit.py` で検証する。
- 競合・産業チェーンの調査では、日本・韓国・台湾・欧州・中国・米国など世界の関連企業を、上場市場や資料言語を理由に除外しない。ただし、特定の海外市場に固有のデータ取得手順、評価基準、通貨例は設けず、各社の公式IR・法定開示・取引所資料を優先する。

`$ARGUMENTS` について、「XX社を理解する」企業深掘り長文シリーズ（3～8本。企業の複雑さに応じて決定。「本数の調整」を参照）を執筆し、WeChat公式アカウント／動画アカウントなどの公開チャネルで発信する。**中核となるIPは「書けること」ではなく「直せること」――金融記事の99%は、このskillのファクトチェック基準に違反している**。

参考例：`reports-jp/{企業名}/{企業名を理解する}/`

## 1. 使用する場面

ユーザーが1社について「教科書レベル」の詳細調査を行い、**長文シリーズ**として公開することを希望する場合に使用する。単独の調査レポートとの違い：
- 3～8本（複雑な企業は8本・約12万字、単純な企業は3本・約3万字）。認識のリセットから意思決定フレームワークまでを一貫して完結させる
- 各記事は独立した読み物として成立する（単独で共有可能）が、バリュエーション／経営陣／価格判断について一貫した枠組みを通す
- 「90分を使って1社を理解したい」読者に向けて書く。証券会社の顧客向けではない

**このskillが適さない場面**：単独の調査レポート、四半期決算コメント、業界調査――これらには `/investment-research`、`/earnings-review`、`/industry-research` を使用する。

## 2. シリーズ構成テンプレート

### 企業の複雑さに合わせて本数を調整する（先に本数、次に各記事を決める）

**本数を8本に固定しない。** 8本は、「複数事業 + 大規模な投資ポートフォリオ + 長期にわたる経営陣の物語」を持つ複雑な企業だからこそ成立する分量である。執筆前に、次の問いを立てる。この企業には「1つの鋭い問い」で独立した記事にできる主軸がいくつあるか。その数だけ記事を書く。

| 複雑さ | 特徴 | 本数 | 例 |
|--------|------|------|------|
| 高 | 複数の事業ラインがそれぞれ独立した事業として成立 + 隠れ資産／投資ポートフォリオ + 経営陣に関する豊富な史料 | 7～8本 | 複合企業 |
| 中 | 2～3本の事業ライン + 重大な時代的変数が1つ | 4～6本 | — |
| 低 | 本業が明確で、中核的な論点が少数に集中 | **3本** | 単一事業企業 |

**3本にまとめる場合の標準的な統合方法**（下記の8主軸は引き続きチェックリストとしてすべて網羅し、3本に組み込む）：

| # | 記事タイトルの方向性 | 組み込む主軸 |
|---|---------|-----------|
| 01 | Xを理解したつもりになっていないか（導入 + 事業と経済的な堀） | 認識のリセット + 経済的な堀 + 利益エンジンの概要 |
| 02 | Xの最大の変数（現在のストーリー／隠れ資産） | 隠れ資産 + AI／時代的変数 |
| 03 | いくらなら買う価値があり、どのシグナルで売るべきか（財務 + 意思決定の最終章） | 財務の深掘り + 経営陣の要点 + バリュエーション判断 |

判断のシグナル：記事の途中で「内容を水増ししている」（同じ事実を言い換えて繰り返している）と気付いた場合は、本数が多すぎるため統合する。反対に、1本が12,000字を超えても収まらない場合は分割する。

### 8主軸の完全テンプレート（複雑な企業向け。単純な企業ではチェックリストとして統合）

| # | タイトルテンプレート | 中核となる問い | 文字数 |
|---|---------|---------|------|
| 01 | Xを理解したつもりになっていないか | 認識のリセット：よくある3つの誤解を打ち破る | 4,000～5,000 |
| 02 | Xの経済的な堀――`<事業の本質を一文で>` | 経済的な堀は深いか、5年後／10年後も残るか | 6,000～8,000 |
| 03 | Xの最大の利益エンジン――`<最も稼ぐ事業>` | 本業は何か、なぜ持続できるか | 6,000～8,000 |
| 04 | Xの帳簿に隠れたもう1社――`<隠れ資産>` | 投資ポートフォリオ／子会社／隠れた価値 | 8,000～10,000 |
| 05 | AI（または現在のストーリー）の時代に、Xは勝者か敗者か | 時代的変数：事業別にAIの影響を分解 | 8,000～10,000 |
| 06 | ウォーレン・バフェット流にXの決算を分解する | 財務の深掘り：粗利率／FCF／自己資本利益率／SBC | 8,000～10,000 |
| 07 | `<経営陣の象徴的な言葉>`――Xの経営陣に資本を託せるか | 資本配分の規律 + 誠実さの検証 + 後継者 | 8,000～10,000 |
| 08 | いくらなら買う価値があり、どのシグナルで売るべきか（シリーズ最終章） | DCFの3シナリオ + レッドライン一覧 + ポジションサイズの枠組み | 10,000～12,000 |

目次索引用に `00-系列说明.md` を1本追加する。これは公開しない。

**構成は企業に合わせること**：このテンプレートをどの企業にも機械的に当てはめてはならない。独立した内容がない記事（投資ポートフォリオを持たない企業では04を書けないなど）は、その企業固有の主軸に置き換えるか、上記の統合方法で少ない本数にまとめる。判断基準は、その記事が「1つの鋭い問い」で独立した読み物として成立するかどうかである。

## 2.5. 各記事の構成テンプレート

各記事は自由に書くのではなく、固定の骨格を持たせる。共通構成：

- **冒頭の引用ブロック**：`> 「Xを理解する」シリーズ · 第0N回 · <主軸>`。冒頭に読了時間を加える
- **第1節は必ずフックにする**：常識に反する一連の数字／異常な曲線／市場が懸念する数字を示し、背景説明から始めない
- **各記事の末尾**：`## 本記事の要点`（5～8項目。数字は本文と厳密に一致）+ `## 次回予告`（鋭い問いで予告し、結論は明かさない）
- **末尾の斜体2行**：`*本記事は「Xを理解する」シリーズ第0N回です...*` + `*本シリーズは公開情報とバリュー投資の枠組みに基づく調査であり、いかなる投資助言も構成しません。*`

各記事固有の骨格：

| 記事 | 骨格 |
|---|------|
| 01 導入 | 市場が株価を繰り返し「再定義」してきた歴史的曲線 → よくある3つの誤解（各誤解を決算データで崩す）→ 「同時にいくつの視点を持つべきか」を示す読解マップ表（02～08へリンク）→ バリュエーションのフックとなる数表（疑問だけを残し、結論は出さない） |
| 02 経済的な堀 | 挑戦者の失敗一覧（実名と年を明記）→ スイッチングコストの本質（ユーザーが移行できないものは何か）→ エコシステムのフライホイール → 5年後／10年後も経済的な堀は残るか → 反対方向の思考実験を1つ（「競合が十分な資本を持てば再現できるか」） |
| 03 利益エンジン | 常識に反する数字で開始 → 中核製品が長寿である理由（価格決定力まで分解）→ 成長余地を定量化（シェア拡大経路 + 反対論：ストーリーが機能しない可能性）→ 組織能力（なぜ製品を継続的に生み出せるか）→ 市場が過小評価する理由 → AI／時代的変数がこの事業に与える影響 → 5年後の姿 |
| 04 隠れ資産 | 上位保有銘柄表（**連結対象外のみを集計**。二重計上を防ぐため、連結対象は別途説明）→ 会計処理の違い（利益計算書に入るもの／入らないもの）→ 「売らない vs 売却の可能性あり」に分類 → 市場がディスカウントする理由（項目別）→ いくつかの意外な発見 → ディスカウントを概算する簡単な方法 |
| 05 AI／時代的変数 | 市場が懸念する数字 → 事業別に勝者／敗者を分解（差が大きいため、全社一括の結論を出さない）→ 中核となる反問（「Xは一点の争いに敗れても、全体で勝てるか」）→ 5～10年で迂回されるシナリオを検討（項目ごとに反論または認める）→ 5つのシナリオ → 今後1年間の監視シグナル一覧 |
| 06 財務 | 異常な曲線で開始 → 利益計算書（粗利率変化の要因分析）→ 基準の選択（Non-IFRS vs GAAP、その理由）→ EPSと自社株買い → バランスシート（ネットキャッシュ）→ キャッシュフローとFCF利回り → 株主還元を「1ドルテスト」で評価 → 自己資本利益率の変化は良いか悪いか → バリュエーションの同業比較 + 時系列比較 → バリュー投資の10項目チェックリストを順に確認 → 決算を3文に圧縮 |
| 07 経営陣 | 中核チーム表 → 重要人物の長期的貢献（形容詞ではなく、具体的な意思決定で示す）→ 利害の一致（持株／報酬の利益に対する比率）→ **誠実さの検証：実際の危機を1件選び、対応を見る** → 5年間の公約達成率（当時の発言原文を項目ごとに照合）→ 資本配分の規律 → 後継者への懸念（避けない）→ 「人を買う3つの問い」（誠実か／有能か／仕事を愛しているか）→ 総合評価 |
| 08 意思決定 | SOTPによる事業別バリュエーション（「何を買うのか」を明確にする）→ 過去のバリュエーション分位 + **「バックミラーはナビではない」と必ず警告** → 将来利益の3シナリオ表（強気／中立／弱気 + 暗黙の成長率。「予測であり事実ではない」と明記）→ レッドライン一覧（抵触 = 即売却ではないが、必ず再検討）→ オッズ思考で締める |

## 3. 執筆スタイルの基準

### 語調

- **直接的で鋭く、無駄を省く**――最初の一文で数字または常識に反する結論を示す
- **バリュー投資の枠組み**――ウォーレン・バフェット／チャーリー・マンガー／段永平／李録の視点を織り交ぜる（ただし名言を羅列しない）
- **立場を事前に決めない**――データを先に提示し、投資ロジックを組み立て、最後に結論を出す
- **賛否両面を示す**――各中核判断に「ただし一方で...」という反対論を添える
- **WeChat公式アカウント向けの読み心地**――冒頭18～20文字だけで内容が成立するようにする（スマートフォンのプレビューを想定）

### 禁止表現

| 禁止 | 理由 | 代替表現 |
|------|------|------|
| 明らかに／必然的に／必ず | 主観的で絶対的 | データは示している／証拠が示している |
| 私は～と考える／私は～と感じる | 主観的な語調 | 削除するか「本フレームワークでは」に変更 |
| 教科書レベル／神業 | 注目を集めるための過剰な称賛 | 具体的な事実を記述 |
| 著しく不整合／著しく過小評価 | 主観が強すぎる | 具体的なディスカウント率を示す |
| 完璧／非の打ち所がない | 一面的な判断 | 反対方向の見方を加える |

### タイトルのスタイル

- **対照的な数字**または**コンセンサスに反する結論**をフックにする（「15年間、7回の挑戦がすべて失敗」、「年収4,292万元は利益の0.0165%にすぎない」）
- 副題は中立的に内容を要約する（「――`<本質的な判断>`」）
- **クリック狙いの比喩を避ける**：「小さなウォーレン・バフェット」、「○○版X」のような表現は使用しない
- 専門読者になじみのある用語を使う（「ウォーレン・バフェット」ではなく「バークシャー」、人名より企業名を優先）

## 4. 厳格なファクトチェック・チェックリスト（中核IP）

### 執筆前から警戒すべき「見せかけの精緻さ」の罠

1. **確率加重期待値**：`30% × A + 50% × B + 20% × C = 期待値 +X%` のような計算は、ほぼすべて無意味である。確率配分が純粋に主観的で、読者に誤った精密感を与える。**シナリオ + 発動条件 + 方向だけを示し、加重期待値は計算しない**。
2. **第三者推計のMAU／シェア**：QuestMobile／七麦／CBNDataなどは基準の差が大きく、同じ時点でも2～3倍の差が出る。**最も信頼できる2つの比較だけをアンカーとして使い、その他は定性的に記述する**。
3. **過去の成長率の線形外挿**：`2025年 +33% × 5年間複利 → 2030年 X` は、金融リテラシーを欠く予測である。**シナリオ仮定 + 上下のレンジ + 約束ではないことを示す**。
4. **未開示の持株比率**：ByteDance、Haltiのような未上場企業の持株比率は**一度も公開されていない**。**レンジを示し、「不明」と明記する**。
5. **単一要因への強い帰属**：競合の失敗 = Xが原因、と決めつけない。複数の原因をすべて列挙し、**本稿では単一の原因に帰属させない**。

### 修正時に必ず実行する7項目

```
□ 1. 記事間の数値整合性：時価総額、Non-IFRS純利益、主要持株比率をシリーズ全体で一致させる
□ 2. 基準の明記：Non-IFRS／GAAP／Non-IFRS-SBC／FCFのどれをどこで使うか、全文で明確にする
□ 3. 二重計上のスキャン：連結子会社を「投資ポートフォリオ」に含めず、SOTPで二重計上しない
□ 4. 同業比較の公平性：「本業PER（現金 + ポートフォリオを控除）」と「競合PER（控除なし）」を比較しない
□ 5. 確率加重をすべて削除：前項を参照
□ 6. 絶対的な表現をすべて弱める：grep "显然|必然|严重|教科书|完美"
□ 7. 第三者データの出典を明記：決算以外の各データの後ろに「（出典：X）」を付ける
```

### モデルの注意事項

執筆前に、**既知の重大な誤りのリスクを先に列挙する**：
- 過去のリターン倍率：累積投資額ベースを必ず使用する（例：Riotは33倍であり、58倍ではない）
- 持株比率：最新の法定開示と決算資料を必ず確認し、過去時点の比率を現在値として使わない
- 「現物配当による分配」の会計処理：IFRIC 17に基づき、処分利益相当額は宣言日に認識する
- 発行済株式総数は反発することがある：SBCの付与が年初に集中すると、株式数が短期的に増加する

## 5. 実行手順

### フェーズ1：調査（記事01～02の執筆前に完了）

1. 企業の直近5年分の年次報告書と最新の四半期報告書を読む
2. 独立したセルサイドの調査レポートを少なくとも3本読む（コンセンサス + 反コンセンサスを探す）
3. `/investment-team` または `/investment-research` で、まず内部調査の基礎資料を作成する
4. 8本の中核的な主張をユーザーと確認する（書き終えてから方向性の誤りに気付くことを防ぐ）

### フェーズ2：執筆（01→最終記事の順に書き、飛ばさない）

- 各記事の完成後、まず `reports-jp/{企業名}/{企業名を理解する}/0X-XX.md` に保存する
- **ディレクトリ競合ルール**：`reports-jp/{企業名}/{企業名を理解する}/` がすでに存在する場合（旧版シリーズ）、上書きも混在もさせない。新シリーズは日付サフィックス付きの新しいフォルダ `reports-jp/{企業名}/{企業名を理解する}-{YYYYMMDD}/` に保存し、旧フォルダはそのまま保持する
- すぐにGitHubへプッシュせず、ユーザーのレビューを待つ
- ユーザーから修正意見を受けた後に変更する
- 修正完了後にのみgit pushする

### フェーズ3：記事間の整合性スキャン（全記事の完成後）

Explore agentを起動し、シリーズ全体について以下を並列にスキャンする：
1. 同じ数値（時価総額、純利益、持株比率）が記事間で一致しているか
2. 同じ用語（FBS、SBC、Non-IFRS）が初出時に説明されているか
3. 参照関係：記事02の「詳しくは記事06を参照」が実際に対応しているか
4. 要点の振り返りと本文の数字が一致しているか

## 6. 修正意見への対応手順

ユーザーから修正意見を受けた場合は、以下の順序で対応する。

### 1. 最初に事実を確認する（すぐに変更しない）

ユーザーから「Xのデータが間違っている」と言われた場合、まずBash／Readで一次データをクロスチェックする：
- ai-berkshireプロジェクト内にある同一企業のearnings／決算レポートを確認
- 企業IR／法定開示を確認
- 「ユーザーが示したデータ vs 調査で確認したデータ vs 以前使用したデータ」の3者を比較

### 2. 修正レベルを判断する

| レベル | 種類 | 対応 |
|------|------|------|
| 🔥 重大な誤り | 数字、要因分析、基準の誤り | 必ず修正。迷う必要はない |
| ⚠️ 主観的 | 強い主観表現、絶対的な表現、クリック狙いの比喩 | 弱めるか削除 |
| 🔬 粒度 | 出典の明記、基準の詳細化 | 優先度は低い。読みやすさとのバランスを取る |
| ❓ 信頼性が低い | 第三者推計の差が大きい | **修正より削除が堅実**（ユーザーの明示的な指示） |

### 3. 修正後に連動箇所を確認する

1カ所を修正したら、まず「他のどの箇所がこの数字／概念を参照しているか」を考える。例：
- 時価総額を変更 → シリーズ全体のPER／本業PER／ディスカウント／FCF利回りも連動して変更
- 持株比率を変更 → 上位10銘柄の順位 + 過去の持株表 + 売却一覧を変更
- 用語の基準を変更 → 初出時の定義 + その後の参照 + 要点の振り返りを変更

### 4. プッシュ後、直ちに報告する

```
プッシュ成功（commit hash）。
[N]カ所の修正概要 [表付き]：
- 変更した内容
- 連動して変更した内容
- まだ変更していない内容

次の指示を待ちます。
```

## 7. このskillが行わないこと

- **読者に代わって投資判断をしない**――すべての記事末尾に「投資助言を構成しない」と記載
- **株価を予測しない**――「シナリオ + 発動条件」だけを提示
- **「期待年率リターン」の加重値を計算しない**――主観的な確率配分は読者を誤解させる
- **「著名投資家Xも保有している」と書かない**――他者のポジションを自分の判断の根拠にすることは、バリュー投資に反する
- **8本すべての執筆を強制しない**――独立した内容が十分にない記事（経営陣に際立った特徴がない企業など）は、他の記事に統合するか、本数を減らす

## 8. コンプライアンスとプライバシー

- すべての公開レポートは**公開情報のみ**を使用する（決算、公式開示、証券会社の調査レポート、著名な第三者機関）
- **ユーザーの個人情報**は一切使用しない（社内での通称、社内IM、未公開のポジション情報）
- プッシュ前にgrepでローカルのユーザー名／`/Users/`／実名などの個人情報フィールドを必ずスキャンする
- 公開時の署名はユーザーの多層的なアイデンティティ戦略に従い、混用しない
