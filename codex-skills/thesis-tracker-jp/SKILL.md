# 日本株の投資仮説トラッカー

`$ARGUMENTS` の日本上場企業について、買付後の投資仮説を作成または点検する。

## 入力モード

- `会社名`：ファイルがなければ新規作成、あれば更新。
- `会社名 仮説作成`：新規に構築。既存がある場合は上書きせず確認する。
- `会社名 四半期点検`：最新決算で更新。
- `会社名 reports/...`：指定ファイルを基準に更新。

標準ファイルは `reports/{会社名}-thesis.md`。見つからないのに利用者が既存を示唆した場合は候補を検索し、確定できなければパスを確認する。別会社のファイルは使わない。

## 設計思想

買付前に売却・再評価条件を書き、決算や重要事象ごとに事実で確認する。株価の下落を仮説破綻と混同せず、撤回条件に触れたときは新しい物語を探す前に元仮説を評価する。

---

## 第1段階：モード判定

1. 引数から会社、コード、操作を読む。
2. 既存ファイルと日付付きスナップショットを検索する。
3. 会社名・コードが一致するか確認する。
4. 未存在ならモードA、存在すればモードB。
5. 既存ファイル衝突時は無断上書きせず、バックアップまたは日付版を作る。

---

## モードA：仮説を作る

### A0. データ収集

株価、PER、PBR、配当、時価総額、最新決算、競争、経営・統治を確認する。既存の `investment-research-jp` または `investment-team-jp` 報告があれば先に読む。

```bash
python tools/jpstock_data.py quote {証券コード}
python tools/jpstock_data.py financials {証券コード}
python tools/financial_rigor.py --locale ja verify-valuation --price {株価} --eps {EPS} --bvps {BPS} --dividend {配当}
```

データは `skills/financial-data-jp.md` に従って二経路照合する。

### A1. 核心仮説は200字以内

次の5点を短く埋める。

```text
私は {買付価格}円で{会社名}を保有する。なぜなら、
1. 事業の本質は___で、稼ぎ方を理解している。
2. 競争優位は___で、拡大／維持している。
3. 経営は___で、信頼の根拠は___。
4. 現在価格は価値範囲の___で、安全余地は___。
5. 誤っていても下方が制御可能なのは___。
```

5文を具体的に書けなければ、仮説は未完成と判定する。

### A2. 核心仮定

3～7個に絞る。

| # | 仮定 | 指標と閾値 | 情報源 | 頻度 | 初期状態 |
|---:|---|---|---|---|---|

売上、価格、数量、粗利、CF、シェア、顧客、設備、競争、経営、政策保有株、親子上場、少数株主保護等から、仮説を直接支える項目だけ選ぶ。

### A3. 赤線

| # | 赤線 | 重大度 | 証拠 | 発動後の行動 |
|---:|---|---|---|---|

例：会計・誠実性問題、核心事業の連続減収、競争優位の突破、規制による収益構造破壊、大規模な非計画希薄化、支配株主による利益相反。赤線発動は直ちに再評価を意味し、自動売買命令とはしない。

### A4. 評価の錨

| 指標 | 買付時 | 楽観 | 基準 | 保守 |
|---|---:|---:|---:|---:|
| 株価 | | | | |
| PER | | | | |
| 時価総額 | | | | |
| 価値範囲 | | | | |
| 安全余地 | | | | |

```bash
python tools/financial_rigor.py --locale ja three-scenario --price {株価} --eps {EPS} --shares {株式数_億株} --growth {楽観} {基準} {保守} --pe {楽観PER} {基準PER} {保守PER} --currency JPY
```

### A5. 保存

`reports/{会社名}-thesis.md` に、作成日、コード、買付価格・比率（提供された場合のみ）、200字仮説、仮定、赤線、評価、空の履歴表を保存する。

## モードB：追跡点検

### B1. 現行仮説を読む

核心仮説、仮定、赤線、評価の錨、前回点検を抽出する。構造が欠ける場合は欠落を明示し、現在の文章から推測できる範囲を分離する。

### B2. 最新データ

最新の有価証券報告書、決算短信、適時開示、会社IRから、決算、経営交代、競争、規制、主要株主、資本政策を取得する。価格だけの変化と事業事実を分ける。

### B3. 仮定を一つずつ確認

| # | 仮定 | 前回 | 最新証拠 | 現在 | 変化 |
|---:|---|---|---|---|---|

- `成立`：最新証拠が支持。
- `辺縁弱化`：許容範囲だが不利な方向。
- `毀損`：明確に支持しない。
- `破綻`：反証された。
- `未確認`：資料がない。

### B4. 赤線

| # | 赤線 | 発動 | 証拠 | 必要な再評価 |
|---:|---|---|---|---|

一つでも発動したら報告冒頭に表示し、安い評価で相殺しない。

### B5. 評価更新

| 指標 | 買付時 | 前回 | 現在 | 変化要因 |
|---|---:|---:|---:|---|

株式数、自己株式、配当・DOE、自己株式取得、政策保有株の売却、親子上場解消等を反映する。

### B6. 追跡報告

```text
1. 仮説健康度
2. 核心仮定の点検
3. 赤線点検
4. 今回の重要変化（500字以内）
5. 評価更新
6. 結論と行動条件
7. 次回の観測事項と日付
```

健康度は次で機械計算する。

`10 - 破綻数×3 - 毀損数×2 - 弱化数×1 - 赤線発動数×5`（最低1、最高10）

| 点 | 意味 | 検討方向 |
|---:|---|---|
| 9～10 | 仮説が強化または維持 | 追加条件を確認 |
| 7～8 | 核心成立、一部弱化 | 維持 |
| 5～6 | 一部毀損 | 警戒を上げる |
| 3～4 | 複数毀損 | 縮小を検討 |
| 1～2 | 赤線または核心破綻 | 退出を含め再評価 |

点数は誠実性赤線を相殺しない。結論は、仮説が `完全／辺縁弱化／毀損／破綻` のどれか、行動条件が `追加／維持／縮小／退出検討` のどれか、次回点検時期を明確にする。

### B7. 履歴更新

既存ファイルの履歴へ追記する。

| 点検日 | 健康度 | 核心変化 | 条件付き行動 | 次回 |
|---|---:|---|---|---|

元の買付時仮説と赤線を消さない。変更する場合は旧文、新文、変更理由、証拠を履歴化する。

## 保存後の監査と失敗時処理

```bash
python tools/report_audit.py --locale ja extract --report reports/{会社名}-thesis.md --market jp
python tools/report_audit.py --locale ja verdict --results '<照合済みJSON>' --report {会社名}-thesis.md --market jp
```

- 基準ファイル不明：更新せず候補パスを示す。
- 最新資料なし：前回状態を維持せず「未確認」とする。
- 数値不一致：期間・単位・会計基準・株式数を合わせる。
- 監査不合格：履歴更新を公開済み扱いにせず修正する。

## 原則

買付前に見直し条件を書く。仮説を観測可能にする。価格下落と仮説破綻を区別する。誤りを新しい物語で隠さず、当初理由と現在理由が違えば新規仮説として記録する。
