# 日本株の投資仮説ドリフト検出

`$ARGUMENTS` について、過去の仮説と新しい仮説を比較し、事実が変わったのか、価格だけが変わったのか、表現だけが変わったのかを判定する。

## 入力モード

- `会社名 旧報告パス 新報告パス`：指定報告比較。
- `会社名 旧日付 新日付`：日付付きスナップショット比較。
- `会社名`：`reports/` から自動探索。
- 基準が一つ以下：基準不足モード。

本スキルは `skills/thesis-tracker-jp.md` の核心仮定、赤線、評価の錨、履歴を標準構造とする。構造がなければ抽出できる範囲だけ比較し、不足を明示する。

## 設計思想

- **事実変化**：売上、利益率、CF、競争、経営、資本配分が検証可能に変化。
- **価格変化**：事業は同じで評価倍率・株価だけが変化。
- **表現変化**：証拠と判断は同じで、語順や語調だけが変化。

証拠が変わったときだけドリフトを認める。結果を知った後で元の買付理由を書き換えない。

## 第1段階：モード判定

1. 二つのパスがあればモードA。
2. 会社名だけならモードB。
3. 比較可能な二つがなければモードC。
4. 会社名・コードが一致しなければ停止し、跨社比較をしない。

## モードA：指定報告比較

### A1. 読取と同一性確認

旧・新から次を抽出する。

- 報告日、会社名、東証コード。
- 200字の核心仮説。
- 核心仮定。
- 赤線。
- 評価の錨。
- 追跡履歴。
- 経営品質と競争優位。
- 行動条件。

構造不足は「構造不足」、抽出不能は「判断不能」とする。存在しない内容を補造しない。

### A2. 証拠の正規化

| 次元 | 旧証拠 | 新証拠 | 期間・定義 | 出典 | 検証可能 |
|---|---|---|---|---|---|
| 評価の錨 | | | | | |
| 核心仮定 | | | | | |
| 赤線 | | | | | |
| 経営品質 | | | | | |
| 競争優位 | | | | | |

同義語、順序、語調の差はドリフトにしない。数値は同じ期間、連結範囲、日本基準／IFRS、円単位へ正規化する。

### A3. 数値と評価

暗算しない。

```bash
python tools/financial_rigor.py --locale ja verify-valuation --price {現在株価} --eps {EPS} --bvps {BPS} --fcf-per-share {1株FCF}
python tools/financial_rigor.py --locale ja verify-market-cap --price {株価} --shares {自己株式控除後株式数} --reported {時価総額} --currency JPY
python tools/financial_rigor.py --locale ja cross-validate --field {項目} --values '{ソース別JSON}' --unit {単位}
python tools/financial_rigor.py --locale ja calc --expr '{変化率の算式}'
```

重要データは二経路照合し、不足・口径不一致は低信頼または要確認とする。

### A4. 固定5次元のドリフト

次元を都合よく増減しない。

| 次元 | 改善 | 不変 | 弱化 |
|---|---|---|---|
| 評価の錨 | 安全余地拡大、価値上方修正 | 実質同じ | 安全余地縮小、前提失効 |
| 核心仮定 | 新証拠が強化 | 状態同じ | 弱化、毀損、破綻 |
| 赤線 | リスク解消 | 未発動で同水準 | 発動または確率上昇 |
| 経営品質 | 誠実性・資本配分が改善 | 旧判断継続 | 信頼・資本配分が悪化 |
| 競争優位 | シェア・価格力・優位が強化 | 実質同じ | 代替・競争で侵食 |

各次元は `改善／不変／弱化／判断不能` のいずれか。政策保有株、親子上場、支配株主、DOE、自己株式取得・消却は経営品質と評価へ反映する。

### A5. 証拠駆動の規則

`改善` または `弱化` には、日付と具体的な新証拠が必須。

- 決算行：売上、粗利、営業CF、受注、純現金、株式数。
- 開示：有価証券報告書、決算短信、TDnet、ガバナンス報告書。
- 出来事：経営交代、行政処分、顧客喪失、競争上の突破。
- 価格：評価変化と事業変化を分離する。

説明できる証拠がなければ `不変` または `判断不能`。不変欄へ架空の証拠を入れない。

### A6. 出力

```text
1. 比較対象と期間
2. 全体結論
3. 5次元のドリフト表
4. 証拠差分
5. 数値・評価の検算
6. 行動条件の移動
7. 不確実性と不足資料
8. 次回追跡項目
```

| 次元 | 旧判断 | 新判断 | 方向 | 触発証拠 | 確信度 |
|---|---|---|---|---|---|

全体結論は必ず答える。

1. 未漂流／正方向／負方向／証拠不足。
2. 評価、事業、経営、競争、赤線のどこから生じたか。
3. 事実変化か価格変化か。
4. 行動条件が監視→検討、検討→保有、保有→縮小等のどちらへ移ったか。
5. 次に必要な決算、開示、説明、競合データ。

## モードB：自動スナップショット比較

### B1. 探索

次を検索する。

- `reports/{会社名}-thesis.md`
- `reports/{会社名}-thesis-*.md`
- `reports/{会社名}/` 配下の `thesis`、`仮説`、`追跡` を含むファイル。

日付が最も古く構造が十分なものを旧、最も新しいものを新とする。利用者が日付を指定した場合はそれを優先する。

### B2. 誤対応を防ぐ

会社名またはコード一致、異なる報告日、抽出可能な仮説構造を確認する。確定できなければ比較を止め、候補パスを提示する。

### B3. モードAを実行

有効な二つが得られたら、A1～A6を省略せず実行する。

## モードC：基準不足

一つしかない、または旧基準がない場合：

1. 「歴史基準がないためドリフト検出不能」と明示する。
2. 記憶や市場印象から旧仮説を作らない。
3. `skills/thesis-tracker-jp.md` で構造化基準を作るよう案内する。
4. 現行報告が十分なら将来比較用の基準として保存する案を示す。

```text
ドリフト検出不能：歴史基準が不足しています。
現在報告：{パス／未発見}
歴史基準：未発見
次の手順：仮説トラッカーで基準を作成し、次の決算または重要事象後に再比較。
```

## 保存、監査、原則

指定があれば `reports/{会社名}-thesis-drift-{YYYYMMDD}.md` に保存し、既存ファイルは上書きしない。

```bash
python tools/report_audit.py --locale ja extract --report {レポートパス} --market jp
python tools/report_audit.py --locale ja verdict --results '<照合済みJSON>' --report {レポート名} --market jp
```

証拠は表現より優先する。事業は株価より優先する。赤線は低いPERで相殺しない。すべての改善・弱化は具体的な新証拠へ追跡可能にする。
