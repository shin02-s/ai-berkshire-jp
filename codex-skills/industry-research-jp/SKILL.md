# 業界投資調査：産業チェーンの全体スキャン + 4人の達人による個別銘柄分析フレームワーク

## 日本語版の共通実行ルール

- 株価、時価総額、財務数値、バリュエーションなどの通貨単位は、日本株では円（JPY）、米国株では米ドル（USD）を使用する。市場横断比較で換算する場合は、元の通貨を併記し、換算日と為替レートを明示する。
- レポートを保存・更新・検索する場合は、`reports/` ではなく `reports-jp/` 配下を使用する。
- データ取得・計算・検証には必要に応じて `tools/` の既存ツールを使用する。日本株では `python tools/jpstock_data.py quote {証券コード}` で株価、`financials` / `filings` でEDINETの財務・開示資料を取得し、重要数値は `tools/financial_rigor.py`、完成レポートは `tools/report_audit.py` で検証する。
- 競合・産業チェーンの調査では、日本・韓国・台湾・欧州・中国・米国など世界の関連企業を、上場市場や資料言語を理由に除外しない。ただし、特定の海外市場に固有のデータ取得手順、評価基準、通貨例は設けず、各社の公式IR・法定開示・取引所資料を優先する。

`$ARGUMENTS` の業界について、産業チェーンを体系的に投資調査する。

## 調査目標

1つの投資テーマ／投資ロジックの連鎖から出発し、次を完了する：
1. 投資ロジックの連鎖を構成する各工程を検証
2. 産業チェーンの完全な全体像を作成
3. 日本・韓国・台湾・欧州・中国・米国など、世界の関連する上場・未上場企業をスキャン
4. 各サブセクターの上位企業について、4人の達人のフレームワークで分析
5. 業界レベルのポートフォリオ配分案を出力

## ステップ1：投資ロジックの連鎖を構築・検証する

### 1.1 投資ロジックの連鎖を描く
「根底にあるトレンド」から「恩恵を受ける投資候補」までの因果関係を矢印で表す。例：
```
根底にあるトレンド A
    → 需要 Bを生む
        → ボトルネック／不可欠な需要 Cを生む
            → 産業チェーン Dが恩恵を受ける
```

### 1.2 工程ごとに検証する
投資ロジックの連鎖にある各矢印へ疑問を投げかけ、証拠を探す：

| 工程 | 中核となる仮定 | 検証方法 | データソース |
|------|---------|---------|---------|
| A→B | | 業界データ／予測を検索 | |
| B→C | | 需給分析を検索 | |
| C→D | | 実例／契約を検索 | |

### 1.3 「すでに発生した検証イベント」を探す
この投資ロジックの連鎖を裏付ける、**契約済み／実行済みの実在する事業イベント**（予測ではない）を列挙する。例：大企業の調達契約、政策文書、業界レポートなど。

## ステップ2：産業チェーンの全体像を作成する

### 2.1 産業チェーンの構造を描く
業界を上流 → 中流 → 下流 → 補助工程に分解する。例：
```
上流：原材料／資源採掘 → 材料加工／精製
中流：中核設備の製造 → システム統合／建設工事 → 新技術の研究開発
下流：運営／サービス → 最終顧客
補助：検査／認証 → 保守サービス → 金融商品（ETF／信託）
```

### 2.2 各工程の「事業特性」を特定する
各工程について、以下を記載する：

| 工程 | ビジネスモデル | 粗利率レンジ | 競争環境 | 参入障壁の種類 | 景気循環性 |
|------|---------|-----------|---------|---------|--------|
| | 資源を販売／設備を販売／サービスを販売／賃料を得る | | 独占／寡占／完全競争 | 資源／許認可／技術／規模 | 強／中／弱 |

### 2.3 「供給上の急所」を明示する
産業チェーンで供給が最も逼迫し、代替が最も難しく、利益率が最も高い工程を特定する――こうした工程に、最良の投資候補が存在することが多い。

## AI調査におけるバイアスの自覚：業界調査特有の罠

業界調査では、AIのデータバイアスが独特な形で増幅される：

**業界レベルのバイアス**：
| バイアスの種類 | 現れ方 | 対応策 |
|---------|------|------|
| 成熟業界への偏り | 伝統的業界（銀行／エネルギー／消費）は資料が非常に多く、AIの分析が「より確実」に見える | 確実性はビジネスモデルから生まれるのであり、調査レポートの本数から生まれるのではない |
| 新興業界の過小評価 | 新興業界（AIアプリケーション／合成生物学など）は資料が少なく、AIの分析が保守的になりやすい | 「現在のデータ」ではなく「最終的な構造を考える思考」で業界価値を判断 |
| 業界大手への偏り | 大企業は小企業より資料がはるかに多く、AIは自然に業界大手を推奨しやすい | 小企業のほうが優れたリスク・リターンを持つ場合がある。AIの分析が短いことを理由に無視しない |
| 上場企業への偏り | 上場企業だけをスキャンすると、産業チェーンの重要な未上場企業を見落とす | 未上場企業を必ず検索し、「将来のIPO候補」と明記 |
| 英語への偏り | AIは英語資料の処理能力が高いため、非英語圏の企業を過小評価する可能性がある | 日本・韓国・台湾・欧州・中国の関連企業を現地語の公式資料でも検索 |

**産業チェーンのスキャンにおけるバイアス対策**：
1. 各工程で「AIが見つけやすい企業」だけでなく、「知名度は低いが優良である可能性のある投資候補」も積極的に検索する
2. 情報が少ない小型株について、分析が短いことを理由に推奨度を下げない。レポートの長さではなく、中核的な問い（事業の本質、経済的な堀、経営陣）で評価する
3. 最終レポートで、各社の「情報の充足度」（A／B／C級）を明記し、AI分析の信頼性を読者が把握できるようにする

## ステップ3：世界の上場企業をスキャンする

TaskツールでバックグラウンドAgentを起動し、この業界の上場企業を網羅的に検索する。

### 検索リスト
- 日本・韓国・台湾・欧州・中国・米国などの関連企業
- ユーザーが投資対象とする市場の上場企業
- 産業チェーン上重要な未上場企業
- 業界ETF
- 重要な未上場企業（将来IPOする可能性あり）

### 各社について収集する項目
- 企業名（正式名称／英語名／必要に応じて現地語名）
- 株式コードと取引所
- 時価総額（概算）
- 一文での説明（産業チェーン上の位置と役割）
- 純粋な投資候補か（原子力専業 vs 多角化企業の一部に原子力事業）
- 産業チェーン上の工程

### 出力形式
産業チェーンの工程別に分類し、工程ごとにスキャンで見つけた全企業を1つの表にまとめる。
次に、投資の確実性で階層分けする：
- **Tier 1**：大型株、純粋な投資候補、業界大手
- **Tier 2**：中型株、専業または事業比率が高い、サブセクター大手
- **Tier 3**：小型株、開発段階、高リスク・高い上昇余地
- **Tier 4**：多角化企業の中で関連事業を持つ大企業

## ステップ4：各工程の上位企業を4人の達人の視点で分析する

産業チェーンの各工程における**Tier 1とTier 2の企業**について、以下の分析を実行する（Tier 3／4は簡潔なコメントでよい）：

### 4.1 事業の本質（段永平）
- この企業が産業チェーンで何をしているか、一文で定義
- 売上高構成と成長率
- 粗利率／純利益率の水準と傾向
- キャッシュフローの特徴
- **追加の問い**：これは優れた事業か？ その理由は？

### 4.2 経済的な堀（ウォーレン・バフェット）
5種類の経済的な堀を評価する（★1～5）：

| 経済的な堀 | 強度 | 根拠 |
|--------|------|------|
| ブランド／価格決定力 | | |
| スイッチングコスト | | |
| ネットワーク効果 | | |
| 規模の経済 | | |
| 技術／許認可の参入障壁 | | |

**追加の問い**：10年後も経済的な堀は残るか？

### 4.3 リスク（チャーリー・マンガー）
- この企業はどのように失敗する可能性が最も高いか？
- 最悪のシナリオでは、いくらの価値があるか？
- 賢い投資家が買わない理由は？

### 4.4 経営陣（段永平 + ウォーレン・バフェット）
- CEO／創業者は誰か？ 重要な意思決定の実績
- 持株比率と利害の一致
- 簡易評価（A／B／C級）

### 4.5 バリュエーションのスナップショット
- 現在のPER／PSR／EV/EBITDA
- 同一工程の競合と比較
- 簡易評価：割高／妥当／割安

### 4.6 推奨度
★1～5で表示する：
- ★★★★★ = 中核ポジション候補
- ★★★★☆ = サテライト・ポジション候補
- ★★★☆☆ = ウォッチリスト
- ★★☆☆☆ = 高リスクのオプション
- ★☆☆☆☆ = 非推奨

## データの抜き取り検査（公開判定プロセス）

レポート保存後にデータの抜き取り検査を実行し、合格した場合のみ公開する：

```bash
# Step 1 — 抜き取り検査リストを抽出（15%を無作為抽出）
python3 tools/report_audit.py extract \
  --report <レポートファイルのパス>

# Step 2 — リストの各項目について信頼できる情報源から数値を取得（skills/financial-data-jp.mdを参照）

# Step 3 — 公開可否の判定を出力
python3 tools/report_audit.py verdict \
  --results '<入力済みJSON>' \
  --report <レポートファイル名>
```

**【公開可】** すべて合格 → レポートを公開可能。**【差し戻し】** 不合格あり → 修正後に再審査。
