# 企業ニュースの脈動：株価の異常変動を迅速に要因分析するチーム

## 日本語版の共通実行ルール

- 株価、時価総額、財務数値、バリュエーションなどの通貨単位は、日本株では円（JPY）、米国株では米ドル（USD）を使用する。市場横断比較で換算する場合は、元の通貨を併記し、換算日と為替レートを明示する。
- レポートを保存・更新・検索する場合は、`reports/` ではなく `reports-jp/` 配下を使用する。
- データ取得・計算・検証には必要に応じて `tools/` の既存ツールを使用する。日本株では `python tools/jpstock_data.py quote {証券コード}` で株価、`financials` / `filings` でEDINETの財務・開示資料を取得し、重要数値は `tools/financial_rigor.py`、完成レポートは `tools/report_audit.py` で検証する。
- 競合・産業チェーンの調査では、日本・韓国・台湾・欧州・中国・米国など世界の関連企業を、上場市場や資料言語を理由に除外しない。ただし、特定の海外市場に固有のデータ取得手順、評価基準、通貨例は設けず、各社の公式IR・法定開示・取引所資料を優先する。

`$ARGUMENTS` について、直近ニュースを調査し、異常変動の要因を分析する。**これは詳細な投資調査ではなく、情報への迅速な対応である**――10分以内に「この企業に最近何が起きたか？ 株価異常変動の本当の原因は何か？ 投資仮説を再検討すべきか？」へ答えることを目的とする。

## 使用する場面

- 保有／注目する株式の株価が大幅に上昇・下落（一般的な発動基準：1日で±5%、1週間で±10%）
- 決算後に株価が異常変動し、市場が何に反応したかを迅速に把握したい
- ニュース見出しを見たが、ノイズか本当のシグナルか判断できない
- **不適切な用途**：包括的な投資調査（`/investment-team` を使用）、決算の精読（`/earnings-review` を使用）、長期的な投資仮説の追跡（`/thesis-tracker` を使用）

## 実行手順

### ステップ1：パラメータと状況を確認する

`$ARGUMENTS` に含まれていない場合は、ユーザーに以下を確認する：

| パラメータ | 説明 | デフォルト |
|------|------|------|
| **企業名** | 日本語／英語／株式コードのいずれも可 | 必須 |
| **時間範囲** | ニュースを遡る日数 | デフォルト14日。決算発表期は7日まで短縮可能 |
| **株価の異常変動** | 上昇／下落幅 + 期間。例：「3日間で12%下落」 | 任意。指定があれば要因分析を絞り込む |
| **重点領域** | 企業イベント / 規制 / 業界 / 市場心理 | デフォルトでは4領域を均等に扱う |

ユーザーが企業名だけを指定した場合は、まず「直近何日間のニュースですか？ 説明したい具体的な株価変動はありますか？」と確認する――**黙って仮定しない**。

### ステップ2：情報の入手可能性を評価する

`investment-team.md` のA／B／C評価を参考にするが、評価軸は異なる：

| 評価 | 特徴 | 調査戦略 |
|------|------|---------|
| **A級（情報が豊富）** | 大型株、メディアのカバレッジが広い、決算発表期 | **ノイズ除去と要因分析**を重視――情報が多すぎるとかえって本当の原因を見つけにくい。各Agentは判断力を持ち、「同じ内容を転載しただけ」の二次ニュースを除外 |
| **B級（情報は中程度）** | 中小型株、通常程度のカバレッジ | 標準モード。各重要イベントに独立した情報源を1～2件付ける |
| **C級（情報が少ない）** | 小型株、新規上場、知名度が低い | 「基礎情報の探索モード」へ移行――変動を説明できるニュースが1件も見つからない可能性がある。**その結論自体に価値がある**（ファンダメンタルズではなく、テクニカル／資金需給の可能性） |

評価を各Agentへ伝え、調査方法に反映させる。

### ステップ3：チームを作成する

TeamCreateでチームを作成する：
- `team_name`：`{企業名}-newspulse`（英小文字。例：`toyota-newspulse`）
- `agent_type`：`team-lead`

### ステップ4：4つの調査タスクを作成する

TaskCreateで以下の4タスクを作成する：

#### タスク1：企業イベントの調査（company-event-scout）

- **subject**：`{企業名}に関する直近{N}日間の企業固有イベントを調査`
- **description**：
  1. **公式開示**：日本株はEDINET／TDnet、米国株はSEC EDGAR、その他は企業IRと現地の法定開示プラットフォームにおける直近の開示
  2. **決算と業績ガイダンス**：最新の四半期報告書／年次報告書、業績予告、決算説明会の要点
  3. **経営陣の行動**：役員変更、買い増し／売却、自社株買い、配当、株式報酬
  4. **重大な事業イベント**：新製品発表、M&A、事業売却、大口顧客／大型受注
  5. **資本取引**：追加資金調達、転換社債、株式交換、重複上場、上場廃止提案
  6. **訴訟とコンプライアンス**：提訴、自主開示したコンプライアンス事案
  7. 各イベントに記載：**日付 / 情報源リンク / 一文での要約 / 株価変動との関連性（高／中／低）**
  8. 日付の新しい順に時系列表を出力

#### タスク2：規制と政策（regulatory-watcher）

- **subject**：`{業界/企業}に関する直近{N}日間の規制・政策変更を調査`
- **description**：
  1. **業界規制**：所属業界の新規制、罰金、是正措置、許認可の変更
  2. **国境をまたぐ政策**：関税、輸出規制、制裁、データセキュリティ、投資規制
  3. **税制**：付加価値税、法人税、個人所得税に関する変更
  4. **独占禁止・競争法**：調査、罰金、M&Aの不承認
  5. **特定業界の政策**：医薬品の集中調達、教育規制、不動産の「3本のレッドライン」、インターネット・プラットフォーム規制など
  6. **金融・為替**：企業へ影響する為替／金利／資本規制の変更
  7. 各政策に記載：**日付 / 情報源 / 企業への直接的影響の程度（直接／間接／無関係）**
  8. 重点判断：「政策上のブラックスワン」が発生したばかりか

#### タスク3：業界と競合（industry-peer-analyst）

- **subject**：`{企業名}の業界構造と競合の直近{N}日間の動向を調査`
- **description**：
  1. **直接競合**：中核競合を3～5社挙げ、直近イベント（決算、製品、価格競争、人事）を1社ずつ確認
  2. **産業チェーンの上流・下流**：上流の原材料／サプライヤー、下流の顧客／チャネルにおける直近の価格、生産能力、受注の変化
  3. **業界全体**：業況データ、出荷量、需要側のシグナル（消費データ、入札データなど）
  4. **代替品の脅威**：新技術、新業態が業界へ与える影響
  5. **業界指数の動き**：同業株の直近の動き。当該企業はアウトパフォーム／アンダーパフォーム／同調のいずれか
  6. 重要判断：**企業固有のイベントか、業界全体のベータ変動か？**
  7. 各イベントに情報源と日付を付記

#### タスク4：市場心理とセルサイド／有力発信者（sentiment-tracker）

- **subject**：`{企業名}に関する直近{N}日間の市場心理と機関投資家見解の変化を調査`
- **description**：
  1. **セルサイド評価の変更**：主要証券会社による直近の評価／目標株価変更
  2. **機関投資家のポジション変化**：法定保有報告、13F開示（米国株）、大量保有報告（日本株）、主要ETFの資金フロー
  3. **空売りデータ**：空売り比率、新たに公表された空売りレポート（ある場合）
  4. **有力発信者の見解**：企業経営者、主要投資家、業界専門家の公開発言を、一次投稿または原典で確認
  5. **噂と未確認情報**：メディア未確認の噂、SNS上の話題。ただし事実として扱わず、確度を明記する
  6. **テクニカルシグナル**：重要な支持線／抵抗線への到達、大口取引、信用取引の異常があるか
  7. 重要判断：**ファンダメンタルズ主導か、市場心理／資金需給主導か？**

### ステップ5：4つのAgentを並列で起動する

**同一メッセージ内でTaskツールを4回並列呼び出しすることが必須**。各Agentの設定：
- `subagent_type`：`general-purpose`
- `run_in_background`：`true`
- `team_name`：`{企業名}-newspulse`
- `name`：対応する役割名（company-event-scout / regulatory-watcher / industry-peer-analyst / sentiment-tracker）

各Agentのpromptテンプレート：

```
あなたは{企業名}ニュース調査チームの「{役割の日本語名}」として、{調査領域}における直近{N}日間のイベントを調査します。

時間範囲：{開始日} ～ {本日の日付}
株価異常変動の背景：{ユーザーが示した変動情報。なければ「特定の異常変動なし。通常の点検」と記載}
情報の入手可能性：{A/B/C}

タスク#{タスク番号}：{タスクsubject}を完了してください。

具体的な調査要件：
{タスクdescriptionの内容}

**調査方法**：
- WebSearchで鮮度を重視した検索を行う（キーワードへ日付または「最近」、「latest」、「2026」を追加）
- 重要イベントはWebFetchで一次情報（開示原文、決算、規制文書）を精読
- 各イベントを「独立した情報源」で検証。噂には2つ以上の独立した情報源が必要
- **煽り見出しに惑わされない**：見出しと本文が一致しないイベントは「見出しが誤解を招く」と明記

**出力形式（重要）**：
1. **中核的な発見**：最重要イベント3～5件。各1～2文
2. **完全なイベント時系列表**（日付の新しい順）：
   | 日付 | イベント | 情報源 | 株価異常変動との関連性 | 持続性 |
3. **当該領域の要因分析結論**：調査したイベントに基づき、「この領域は株価異常変動を説明できるか？ 確信度はどの程度か？」へ回答
4. **データ不足に関する声明**：見つからない情報、疑問が残る情報、追加情報を待つ必要がある事項
5. 「事実」と「推測」を厳格に区別し、CLAUDE.mdの客観性原則に従う

**完了後**：
1. TaskUpdateでタスクをcompletedに変更
2. SendMessageで完全版調査レポートをteam-leadへ送信（type: "message", recipient: "team-lead"）
```

### ステップ6：進捗をリアルタイムで追跡する

- 調査レポートを1件受け取るたびに、その領域の中核的な発見を3件ユーザーへ表示
- 4件すべてが揃うまで待つ
- すべて揃った後、SendMessageで4つのAgentへshutdown_requestを送信

### ステップ7：team-leadによる総合要因分析

4件の調査レポートを統合し、**異常変動の要因分析レポート**を出力する（調査レポートではなく、「判断」を重視）：

---

#### 1. 一文での要因分析
> 30～60字で説明：今回の株価異常変動の主因 + 副次要因 + 性質の判断（価値に関わるイベント／市場心理の変動／不明）

#### 2. 完全なイベント時系列（4領域を統合）

すべての領域のイベントを日付の新しい順で統合する：

| 日付 | 領域 | イベント | 情報源 | 変動要因としての比重 |
|------|------|------|------|-----------|
| 2026-04-30 | 企業 | XX | リンク | 🔴 高 |
| 2026-04-29 | 業界 | XX | リンク | 🟡 中 |
| 2026-04-28 | 市場心理 | XX | リンク | ⚪ 低 |

比重の凡例：🔴 高（単独で変動を説明できる）/ 🟡 中（一部に寄与）/ ⚪ 低（背景ノイズ）

#### 3. 異常変動の要因分析表

| 説明候補 | 証拠 | 反証 | 確信度 | 持続性 |
|---------|------|------|------|--------|
| 例：決算未達 | 売上高が予想を5%下回り、粗利率が低下 | 経営陣は一時要因と説明 | 高 | 短期1～2週間 |
| 例：業界ベータ | 同業他社も同時期に8%下落 | 当該株の下落幅は業界を明確に上回る | 中 | 業界と同調 |

#### 4. 性質の判断（中核となる結論）

1つにチェックを付ける：

- [ ] **価値に関わるイベント**：ファンダメンタルズに実質的な変化（業績、経済的な堀、経営陣、最終構造）があり、投資仮説の再検討が必要
- [ ] **市場心理／テクニカル変動**：ファンダメンタルズに変化はなく、資金需給／市場心理／ベータ主導。機会またはノイズと見なせる
- [ ] **本当の原因が不明**：株価変動の大きさに見合うイベントが見つからない――**最も危険な結論**。市場が何かを先に知っている（内部情報／先回り）か、情報源を見落としている可能性
- [ ] **混合**：一部は価値に関わるイベント + 一部は市場心理による増幅

#### 5. 各領域の調査要約

各領域の最重要発見3～5件 + 変動要因への寄与度。

#### 6. 行動案

| 行動 | 推奨するか | 理由 |
|------|--------|------|
| 投資仮説の再検討を開始（`/thesis-tracker`） | | |
| 決算の詳細精読を開始（`/earnings-review`） | | |
| 経営陣の再評価を開始（`/management-deep-dive`） | | |
| ポジション調整（買い増し／ポジション縮小／変更なし） | | 注意喚起のみ。最終判断はユーザーが行う |
| 観察のみ | | |

#### 7. 今後7～30日間の追跡リスト

- [ ] 開示待ちイベント1（例：5/15の決算説明会）
- [ ] 追跡待ち指標2
- [ ] 重要な観察シグナル3

#### 8. 情報不足に関する声明

今回の調査で解決できなかった疑問、見つからなかった情報、追加開示を待つ必要がある事項を正直に列挙する。**推測で空白を埋めず、「不確実」と明記する。**

## 重要原則

1. **網羅性より速さ**――このskillの中核価値は、10～15分以内に要因判断を出すこと。詳細分析へ入り込まない（それは他のskillの役割）
2. **列挙より要因分析を優先**――イベントを見つけるのは難しくない。難しいのは「どのイベントが今回の株価変動に見合うか」を判断すること。足し算ではなく、引き算をする
3. **「不明」に正直であること**――主因が見つからない場合は「本当の原因は不明」と明記する。無理に因果関係を作るより価値がある（市場が悪材料を先回りしている可能性）
4. **立場を事前に決めない**――保有しているからといって「市場心理の変動だから問題ない」と考えない。証拠が示す方向をそのまま記載
5. **「カタリスト」と「偶然」を区別**――同時期に発生したイベントが変動の主因とは限らない。影響の規模が変動に見合うかを見る
6. **情報の入手可能性を尊重**――C級企業ではニュースが1件も見つからない可能性があり、その結論自体を記載する
7. **`CLAUDE.md` の客観性原則に従う**――すべての判断にデータソースを付け、事実と見解を区別
8. **ユーザーに代わって意思決定しない**――要因分析と行動案の一覧を提示するが、売買判断はユーザーが行う
